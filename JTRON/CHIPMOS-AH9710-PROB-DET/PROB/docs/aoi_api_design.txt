All five features (lap_var, grad_mag, edge_den, mean, std) are pixel-density sensitive — the same physical probe tip gives different numeric feature values at a different resolution — so the model only generalizes cleanly when the ROI the AOI receives has roughly the same pixel dimensions and the same physical content as training.

Option A — easy mode: match the training resolution (no rescaling needed)

Have your colleague configure:

- Full RCM snapshot resolution: 1540 × 1050 px (1050 and 1051 both work — one-pixel delta is noise).
- Camera field of view / scale: framed so the probe tip region sits inside reference_roi × full_frame, i.e. between
  - x: 385 px – 770 px (the middle-left 25% strip)
  - y: 473 px – 893 px (the middle-lower vertical band)
- Monitor's capture_roi (in monitor.json):
"capture_roi": { "x": 385, "y": 473, "w": 385, "h": 420 }
- Monitor uploads the 385 × 420 crop → AOI runs directly, no resize anywhere.

Option B — flexible mode: any resolution, monitor resizes

If they can't lock the camera at 1540 × 1050, the monitor side does a one-line resize before uploading. Logic the monitor should run every tick:

h, w = rcm_snap.shape[:2]                      # whatever the camera gives
rx1, ry1, rx2, ry2 = (0.25, 0.45, 0.50, 0.85)  # from /api/v1/config
x1, y1 = int(w * rx1), int(h * ry1)
x2, y2 = int(w * rx2), int(h * ry2)
crop = rcm_snap[y1:y2, x1:x2]
crop = cv2.resize(crop, (385, 420), interpolation=cv2.INTER_AREA)  # normalize to training size
# POST crop as the `file` field

This preserves the content the model expects and absorbs any resolution they pick. INTER_AREA is the right interpolation for downsizing (preserves edges without aliasing); if their camera is lower than 1540 × 1050, use INTER_CUBIC instead.

Option C — change the field of view (zoom in / zoom out)

This one needs recalibration, not resizing. If they tilt/zoom/move the camera so the full frame now shows a different physical area of the probe/die, the ROI will see different content — the model's feature statistics will shift, and lap_var / grad_mag may no longer separate cleanly.
