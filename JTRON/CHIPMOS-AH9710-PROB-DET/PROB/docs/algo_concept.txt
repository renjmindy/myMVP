Here's the definitions table for the 5 features used in the logistic classifier. All are computed on the grayscale ROI (after a 5×5 Gaussian blur where noted).

Feature: lap_var
What it measures: Sharpness / edge energy. How much fine spatial detail the ROI contains — flat regions are near 0, textured regions are high.
How it's computed: var( Laplacian(blur(gray)) ). The Laplacian is the 2nd spatial derivative (∂²I/∂x² + ∂²I/∂y²); variance of that response summarizes edge
  activity in one number.
Range (this dataset): contact 21–31 vs non-contact 15–20 (zero overlap)
Why it helps: A seated probe produces sharp tip/pad boundaries; an idle non-contact scene is smoother. Classic "focus measure" from autofocus literature.
────────────────────────────────────────
Feature: mean
What it measures: Average brightness of the ROI. Simple intensity midpoint, 0 = pure black, 255 = pure white.
How it's computed: gray.mean()
Range (this dataset): contact 38–52 vs non-contact 34–48 (heavy overlap)
Why it helps: Weak signal: contact can slightly brighten the area via reflections, but overall illumination varies more than contact state does. Keeps a
  small coefficient (+0.37) in the model.
────────────────────────────────────────
Feature: std
What it measures: Contrast within the ROI — how spread out the pixel brightnesses are around the mean. High = mix of dark & bright pixels; low = uniform.
Why it helps: Contact adds a bright feature against a darker backdrop → higher contrast. Noisier than lap_var because it ignores where the variation is.
────────────────────────────────────────
Feature: edge_den
What it measures: Edge density — fraction of ROI pixels that are strong edges (as decided by a two-threshold edge detector).
How it's computed: Canny(blur(gray), 50, 150) → count of edge pixels ÷ total pixels. Canny uses hysteresis (keep an edge if it's connected to a very strong
  one) which is more noise-robust than raw thresholding.
Range (this dataset): contact 0.02–0.08 vs non-contact 0.00–0.04 (small overlap)
Why it helps: Counts well-defined edges, not just any derivative response. A pressed probe shows a distinct silhouette → many connected edge pixels; empty
  scenes have almost none.
────────────────────────────────────────
Feature: grad_mag
What it measures: Average gradient magnitude — how steeply intensity changes per pixel, averaged over the ROI. First-derivative analogue of lap_var.
How it's computed: Sobel_x = ∂I/∂x, Sobel_y = ∂I/∂y, then mean( √(Sobel_x² + Sobel_y²) ). 3×3 Sobel kernels.
Range (this dataset): contact 40–55 vs non-contact 8–38 (zero overlap)
Why it helps: First-derivative features and second-derivative features (lap_var) capture different aspects of structure: gradient tells you edge strength
  overall, Laplacian tells you concentration of that structure. Having both makes the classifier robust when one gets fooled.

Why this set works for "universal across probe types"
- lap_var and grad_mag both separate the two classes perfectly on this data — if one gets confused by a new probe shape, the other is likely still intact.
- edge_den is based on a qualitatively different pipeline (Canny's hysteresis) — a different failure mode than the derivative-based features.
- mean + std are weak on their own but add cheap context; the logistic regression down-weights them automatically (weights 0.37 and 0.05) so they don't hurt when uninformative.

So the five features span two derivative orders (gradient + Laplacian), a dedicated edge detector (Canny), and raw intensity statistics (mean, std) — roughly orthogonal signals, which is what gives the model its resilience when you add new probe types.


# how did you standardize and then do the logistic regression?

Two stages: feature-wise z-score standardization, then gradient-descent logistic regression on the standardized matrix. Both are hand-rolled in ~15 lines of NumPy — no sklearn.

1. Standardization (z-score)

Each feature has very different units (lap_var in tens, edge_den in 0.0X). Putting them on the same scale makes the weights interpretable and gradient descent well-conditioned.

For every feature j, over the 24 training rows:

μⱼ = mean(Xⱼ)        # column mean
σⱼ = std(Xⱼ)         # column std (unbiased not corrected; numpy default)
Xnⱼ = (Xⱼ − μⱼ) / σⱼ    # now μ(Xnⱼ) = 0, σ(Xnⱼ) = 1

One safeguard: if any σⱼ == 0 we clamp it to 1 so we don't divide by zero.

The computed (μ, σ) are saved into calibration.json and used unchanged at inference — new images are standardized with the training statistics, never recomputed.

2. Logistic regression

Model. Binary classifier p(contact | x) = σ(w·xₙ + b) with σ(z) = 1/(1+e^(−z)).

Loss. Binary cross-entropy with an L2 penalty on w:

L(w, b) = −(1/N) Σᵢ [ yᵢ log pᵢ + (1−yᵢ) log(1−pᵢ) ] + (λ/2) ‖w‖²

L2 (λ = 0.01) keeps weights small on a 24-sample dataset so we don't memorize noise.

Gradients.
∂L/∂w = (1/N) Xₙᵀ (p − y) + λ w
∂L/∂b = mean(p − y)

Optimizer. Full-batch gradient descent, 5000 iterations, learning rate 0.1. No mini-batches (dataset is tiny), no momentum, no early stopping. The loop literally is:

w = zeros(d); b = 0
for _ in range(5000):
    p = 1 / (1 + exp(−(Xn @ w + b)))
    g = p − y
    w −= 0.1 * (Xn.T @ g / N + 0.01 * w)
    b −= 0.1 * g.mean()

Initialization. w = 0, b = 0. Fine for logistic regression because the loss is convex — any starting point converges to the same optimum.

3. Inference (identical pipeline, saved parameters)

At request time the API does, for each incoming image's ROI:

x  = [lap_var, mean, std, edge_den, grad_mag]        # 5 features
xn = (x − μ) / σ                                      # same μ,σ from training
z  = w · xn + b
p  = 1 / (1 + exp(−z))
is_contact = (p >= 0.5)

Concretely from calibration.json:

Why this choice over alternatives

- No sklearn dependency — keeps the deployable surface tiny (numpy + opencv + fastapi only).
- Convex loss — no local minima, no seed-dependence, no "did it converge?" anxiety.
- L2 instead of L1 — we want all features to participate (robustness across probe types), not have the model drop any of them.
- No validation split — N=24 is too small to carve out a holdout. The L2 penalty is the only regularizer; real validation will happen when you add more probe types.

so now you combine all five of them?

Yes. Every predict call computes all five, standardizes them, and feeds the whole vector into the logistic regression — the decision is one weighted sum of all five features, not a chain of per-feature gates.

Concretely, for a given ROI the API does:

z = 1.948 * z(lap_var)
  + 0.368 * z(mean)
  + 0.048 * z(std)
  + 1.586 * z(edge_den)
  + 1.189 * z(grad_mag)
  − 1.396          # intercept

p(contact) = 1 / (1 + e^(−z))
Contact if p ≥ 0.5

where z(f) = (f − μ_f) / σ_f.

Why "all five" is not the same as "all five equally"

Because the loss was convex and we ran to convergence, the weights auto-rank the features by evidence:

If you later retrain on a mix of probe types and find one feature stays near zero across all types, you can drop it then — but on the current data there's no reason to.
