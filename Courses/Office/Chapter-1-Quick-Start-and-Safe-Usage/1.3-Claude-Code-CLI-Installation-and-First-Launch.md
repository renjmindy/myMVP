# 1.3｜Claude Code CLI Installation and First Launch

## Learning Objectives

- Understand the basic concepts and operations of the terminal, even with absolutely no command-line experience;
- Complete the installation of Claude Code CLI on your own computer;
- Complete account login / API Key authentication;
- Successfully run the first command and get familiar with the basic interactive interface;
- Know the troubleshooting order to follow when installation errors occur.

## Suggested Duration

30 minutes (step-by-step hands-on, with the instructor demonstrating in sync while students follow along)

## Prerequisite Knowledge

- No command-line experience required — this lesson explains basic terminal operations from scratch;
- Node.js already installed on the computer (version 18+ recommended); this lesson will teach you how to check and install it.

## Course Outline

### 0. Terminal Zero-Basics: Opening the Terminal, Getting to Know the Command Line

Give students who have never touched the command line a reassuring starting point — the terminal is far less technical than it seems; day to day, you'll only repeatedly use a handful of fixed commands.

**What is a terminal**: a plain-text interface where you type a command, press Enter, and the computer executes it and prints the result — a more direct way of communicating with the computer than clicking around a graphical interface.

**How to open it**:

- macOS: press `Cmd + Space` to open Spotlight Search, type `Terminal`, and press Enter;
- Windows: click the Start menu, search for `PowerShell`, and press Enter.

**Get to know a few basic commands you'll use throughout the whole course**:

| Command (macOS/Linux) | Command (Windows) | Function | Example |
|---|---|---|---|
| `pwd` | `cd` (with no argument) | Show the folder you're currently in | `pwd` |
| `ls` | `dir` | List the files and subfolders in the current folder | `ls` |
| `cd folder_name` | `cd folder_name` | Enter a folder | `cd Desktop` |
| `cd ..` | `cd ..` | Go back up one folder level | `cd ..` |

**Hands-on**: Open the terminal live and run, in order, `pwd` → `ls` → `cd Desktop` (or any folder that exists) → `pwd` → `cd ..`, to get an intuitive feel that "the terminal is really just typing instead of clicking through folders with a mouse."

> Mindset check: the terminal looks "very technical," but day to day you'll only repeat these few commands — there's no need to memorize more than that. For the installation steps that follow, all you need to do is copy and paste the commands provided in this lesson; you don't need to understand the underlying principles behind them.

### 1. Pre-Installation Checklist

- [ ] Node.js is installed (`node -v` shows a version number);
- [ ] npm is installed (bundled with Node.js; check with `npm -v`);
- [ ] An Anthropic account has been registered (for login authentication);
- [ ] The terminal / command prompt opens normally (macOS: Terminal / iTerm; Windows: PowerShell / Windows Terminal; Windows students are encouraged to install WSL2 for a more Unix-like experience, though this is not required).

### 2. Installation Steps

**macOS / Linux:**

```bash
npm install -g @anthropic-ai/claude-code
```

**Windows (PowerShell):**

```powershell
npm install -g @anthropic-ai/claude-code
```

> Instructor note: if a student's computer lacks sufficient permissions for a global npm install, avoid having macOS/Linux students use `sudo npm install -g`. Instead, prioritize guiding them to configure a user-level global npm directory, or use nvm to manage the Node version — this avoids permission issues at the root.

After installation, verify with:

```bash
claude --version
```

Seeing a version number confirms a successful installation.

### 3. First-Time Login

Run in the terminal:

```bash
claude
```

The first run will walk you through login:

1. Choose a login method (Anthropic account / Claude Pro-Max subscription / API Key, depending on the student's account type);
2. A browser will automatically open an authorization page — log in and confirm authorization;
3. After authorization succeeds, return to the terminal — seeing the welcome screen confirms that login is complete.

> For students logging in via API Key, key retrieval and secure management will be covered in detail in 1.4 — for now, just complete this step of "getting it running."

### 4. Getting Familiar with the First-Launch Interface

After launching, students will see an interactive prompt (similar to a chat input box). Walk them through:

- The input box: you can type directly to ask a question / assign a task;
- The status bar at the bottom: shows the current model and the current working directory;
- For the first input, suggest a "zero-risk" task, for example:

```
> Hi, please introduce yourself, and tell me which directory on this computer you can currently see
```

Observe how it answers regarding the "current working directory" — this helps students build an intuitive understanding that "it's running on my actual file system."

### 5. Exiting and Re-Entering

- To exit: `Ctrl + C` (twice), or type `/exit`;
- To re-enter a specific project folder: first `cd` into the target folder in the terminal, then run `claude` — it will automatically use that folder as its workspace (the workspace concept is covered in detail in 2.1).

## Troubleshooting Order for Common Installation Issues

1. **`command not found: claude`**: this means the bin directory from the global install wasn't added to the system PATH — check whether the path shown by `npm config get prefix` is included in PATH;
2. **Permission error (EACCES)**: don't force the install with `sudo` — instead use nvm, or adjust the permissions on the npm global directory;
3. **Node version too old**: upgrade to Node 18 or above;
4. **Login stuck on the browser authorization page**: check whether the system's default browser is being blocked, or whether a corporate network proxy is intercepting the authorization callback;
5. **Corporate network / proxy environment**: you may need to configure the `HTTPS_PROXY` environment variable — this is covered as part of the general configuration approach for proxies and third-party access in 1.4.

## Frequently Asked Questions

**Q: Do I have to know how to use the command line?**
A: You only need to master a few actions: "open the terminal, type a command, press Enter." The course will spell out each command in full — just type it as shown; you're not required to understand the full principles behind the command line.

**Q: What's the difference between Windows and Mac?**
A: The installation commands themselves are identical; the main differences are in how you open the terminal application and in path notation (Windows uses backslashes, Mac/Linux use forward slashes). Windows students are encouraged to use PowerShell or WSL2.
