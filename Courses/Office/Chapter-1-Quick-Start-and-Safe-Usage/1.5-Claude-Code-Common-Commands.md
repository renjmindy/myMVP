# 1.5｜Claude Code Common Commands: Turning Conversation into a Controllable Workbench

## Learning Objectives

- Master 8–10 commonly used, high-frequency slash commands;
- Master the syntax for referencing files with `@` and running terminal commands with `!`;
- Understand the differences between permission modes (Plan Mode / auto-accept / manual confirmation) and how to switch between them;
- Be able to independently perform everyday operations such as "clearing context, compacting a conversation, switching models."

## Suggested Duration

30 minutes (hands-on deep dive, practicing item by item)

## Prerequisite Knowledge

- Have completed 1.3 and can launch the CLI normally.

## Course Outline

### 1. Overview of Slash Commands

In the Claude Code input box, typing `/` triggers built-in commands. Walk students through each one hands-on:

| Command | Function |
|---|---|
| `/help` | View all available commands |
| `/clear` | Clear the current conversation context and start a brand-new session |
| `/compact` | Compact the current conversation history, keeping the key points and freeing up context space |
| `/init` | Generate a `CLAUDE.md` initial configuration file in the current project (detailed in 2.2) |
| `/model` | View / switch the currently used model tier |
| `/permissions` | View / adjust the current permission mode settings |
| `/agents` | View / manage Sub Agents (detailed in 2.5) |
| `/review` | Initiate a review of the current code changes |
| `/add-dir` | Bring an additional directory into the current workspace's accessible scope |
| `/exit` | Exit Claude Code |

> Instructor note: don't require students to memorize these — the key is to demonstrate `/help` as an "always-available lookup point," which lowers the memorization burden.

### 2. Referencing Files with `@`: Pinpoint Precision

Use `@filename` directly within your input to reference a specific file — Claude will automatically locate and read that file's contents, without you having to manually describe the path.

Hands-on example:

```
> Help me check @report.md for spelling mistakes
```

Have students notice: an `@` reference is more precise, uses fewer tokens, and is less prone to reading the wrong file, compared to a vague description like "go find that report file."

### 3. Running Terminal Commands with `!`: Run Commands Without Leaving the Conversation

Starting the input box with `!` hands the command directly to the terminal for execution — the result appears in the conversation log, with no need to exit Claude Code.

Hands-on example:

```
! ls -la
! git status
```

Emphasize the use case: when a student wants to manually confirm the current directory's state, or run a single command to see the effect, without interrupting the flow of conversation with Claude.

### 4. Permission Modes: The Core Safety Mechanism

This is where the "safe usage" thread running through this chapter gets put into practice. Walk students through the three permission tiers (the exact naming may change across versions — the instructor should verify against the current version):

1. **Ask mode (default)**: for operations involving writing/modifying/executing commands, confirmation prompts appear step by step;
2. **Plan Mode**: performs only read-only analysis and outputs a plan, without making any actual changes, letting you review the plan before deciding whether to execute it;
3. **Auto-accept mode**: in scenarios you explicitly trust, skips step-by-step confirmation and lets Claude complete the task continuously.

**Safety principles to emphasize in class:**

- For beginners / unfamiliar projects / production environments, prioritize **Ask mode** or **Plan Mode**;
- Only consider auto-accept mode for repetitive work where you can fully bear the consequences and the task scope is clearly defined;
- For irreversible operations such as deleting files, force-pushing code, or sending outbound messages, it's advisable to form the habit of "taking one more look," regardless of which mode you're in.

Hands-on demonstration: use `/permissions` to view the current mode, switch to Plan Mode, have Claude plan a "clean up temporary files" task, and observe how it only produces a plan without executing it directly.

### 5. Context Management: `/clear` vs. `/compact`

- `/clear`: a complete wipe, suited to switching to an entirely unrelated new task;
- `/compact`: keeps key information while compacting redundant details, suited to situations where the task isn't finished yet but the conversation has grown very long, and you're worried it might affect the quality of subsequent understanding.

## In-Class Combined Exercise

Give students a small, real task that requires combining the commands learned in this lesson:

```
1. Use @ to reference a sample file and have Claude summarize its content
2. Use ! to manually run an ls command to verify the directory structure
3. Switch to Plan Mode and have it plan the steps to "write the summary into a new file"
4. Confirm and execute, then use /compact to compact the conversation
```

## Frequently Asked Questions

**Q: What if I can't remember the commands?**
A: `/help` is always available for lookup — you don't need to memorize them; they'll become familiar naturally with use.

**Q: Is Plan Mode safer, and should I always use it?**
A: Plan Mode sacrifices some efficiency (since every step requires your confirmation). For everyday simple tasks, the default Ask mode is sufficient — Plan Mode is better suited to scenarios where "the task is complex and the consequences are significant."
