# 1.6｜Advanced Commands and Custom Commands: Turning Claude Code into Your Own Work System

## Learning Objectives

- Understand the principle and purpose of "custom slash commands";
- Be able to create a custom command of your own and reuse it within a project;
- Build an initial understanding of three advanced concepts — Hooks, Sub Agents, and Skills (covered in detail in Chapters 5, 2, and 7 respectively);
- Understand the idea of "packaging repetitive prompts into a command," laying the groundwork for automation in later chapters.

## Suggested Duration

30 minutes

## Prerequisite Knowledge

- Have completed 1.5, and are familiar with basic slash commands and permission modes.

## Course Outline

### 1. Why Custom Commands Are Needed

- Pain point: there are many tasks where you repeatedly say something similar to Claude (for example, "help me write a weekly report in our company's format" or "help me check this code for security vulnerabilities"). Retyping it every time is both time-consuming and prone to inconsistent phrasing;
- Solution: save that "repeated prompt" as a custom command, so afterward you only need to type `/weekly-report` or `/security-check` to trigger it in one go.
- Analogy: built-in commands are "factory-set shortcuts," while custom commands are "shortcuts you set up yourself."

### 2. Where Custom Commands Are Stored

Claude Code reads Markdown files from the `.claude/commands/` folder inside the project directory — each file corresponds to one command, and the filename is the command name.

```
project-root/
  .claude/
    commands/
      weekly-report.md
      security-check.md
```

- Project-level commands: only take effect within the current project, suited to project-specific workflows;
- Personal global-level commands: stored in a corresponding configuration location under your user directory, available across all projects — suited to your own general habits (such as "rewrite this in a more conversational tone").

### 3. Creating a Custom Command Hands-On

Using "generate a weekly report" as an example:

1. Create `.claude/commands/weekly-report.md` in the project root directory;
2. Write a prompt template into it, for example:

```markdown
Based on the work log I provide next, generate a structured weekly report including:
1. This week's completed items (sorted by priority)
2. Problems encountered and how they were resolved
3. Next week's plan
Keep the tone professional and concise — do not use exaggerated adjectives.
```

3. After saving, return to Claude Code and type `/weekly-report`, and observe whether it automatically applies this template;
4. Guide students in discussing: what other prompts that repeatedly come up in their own work could be packaged into a command? (Content-creation students might think of a "viral headline generator"; operations students might think of a "competitor analysis template.")

### 4. Commands Can Take Arguments

Custom commands support passing in arguments, letting the same command template adapt to different inputs — for example, `/weekly-report This week I mainly worked on A, B, and C`, where the specific content is appended directly after the command. Have students try this briefly once, without going deep into the syntax details (to avoid information overload — the details are saved for the "Templates and Skills" topic in Chapter 7).

### 5. A Preview of Advanced Concepts (Building Awareness, Not an In-Depth Explanation)

This lesson only establishes "what this is and which future chapter covers it in detail," to avoid information overload:

| Concept | One-Sentence Definition | Chapter Covered in Detail |
|---|---|---|
| **Hooks** | Automatically trigger a piece of logic when a specific event occurs (such as before every file save), making your workflow more controllable | Chapter 5 |
| **Sub Agent** | Splits a large task among multiple "dedicated helper agents" working in parallel, each handling its own part | Chapter 2, Section 2.5 |
| **Skills** | Packages an entire workflow into a "one-click callable" capability bundle, more complete than a custom command | Chapter 7 |
| **CLAUDE.md** | A project's "instruction manual" file, letting Claude understand the project's background and conventions in advance | Chapter 2, Section 2.2 |

> Instructor note: use a "capability pyramid" diagram to present this — custom commands (simplest) → Hooks (process control) → Sub Agents (parallel division of labor) → Skills (packaged reuse) — to help students build a mental map for the rest of the course.

## Frequently Asked Questions

**Q: What's the difference between a custom command and "saving a prompt in a notes app and copy-pasting it"?**
A: A custom command is integrated directly into Claude Code — typing `/command-name` triggers it instantly, with no need to switch apps to copy and paste. It can also be set up differently per project, support arguments, and later be upgraded into a more elaborate Skill.

**Q: What if I make a mistake writing a command?**
A: Just edit the corresponding Markdown file directly — save your changes, and the next call to that command uses the new version. There's no extra "publishing" step.
