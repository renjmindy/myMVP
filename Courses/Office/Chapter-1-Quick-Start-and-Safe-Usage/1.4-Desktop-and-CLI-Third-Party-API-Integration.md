# 1.4｜Claude Desktop and Claude Code CLI Third-Party API Integration

## Learning Objectives

- Understand the difference between "connecting directly to the official API" and "using a third-party / relay API";
- Be able to configure a custom `ANTHROPIC_BASE_URL` / `ANTHROPIC_API_KEY` in Claude Code CLI;
- Be able to configure the equivalent third-party access method in Claude Desktop;
- Grasp the basic principles of secure key management, and understand the risks of third-party relays.

## Suggested Duration

25 minutes

## Prerequisite Knowledge

- Have completed 1.3, with the CLI launching normally.

## Course Outline

### 1. Why "Third-Party APIs" Exist at All

- Official direct connection: use your Anthropic official account / API Key directly, going through official billing and official servers;
- Third-party relay: access the model through a compatible interface provided by a third-party service provider, commonly motivated by pricing plans, payment method convenience, or regional access convenience;
- **Explain the pros and cons from a neutral standpoint**, without endorsing any specific brand:
  - Advantages: potentially better pricing, more convenient payment;
  - Risks: data passes through a third-party server in transit, creating privacy and compliance risks; service stability and how quickly model versions get updated are outside your control; your account/quota could become unusable due to problems on the provider's end.

> Instructor note: the core point of this section is not "which relay service to recommend," but rather "teaching students to understand the principle behind the configuration (base_url + api_key), so they can judge and choose for themselves."

### 2. Core Concept: Two Environment Variables

For Claude Code CLI, recognizing a third-party integration essentially comes down to replacing two configuration items:

| Variable Name | Function |
|---|---|
| `ANTHROPIC_API_KEY` | Your identity credential (the key) |
| `ANTHROPIC_BASE_URL` | The server address requests are actually sent to |

By default, the official setup uses Anthropic's official address; configuring a third-party relay essentially means pointing `ANTHROPIC_BASE_URL` at the address provided by the other party, and using the `ANTHROPIC_API_KEY` they provide.

### 3. Hands-On CLI Configuration

**Method 1: Temporary (current terminal session only)**

```bash
export ANTHROPIC_API_KEY="your key"
export ANTHROPIC_BASE_URL="the address provided by the third party"
claude
```

**Method 2: Persistent (write into your shell config file)**

Append to `~/.zshrc` (default on macOS) or `~/.bashrc`:

```bash
export ANTHROPIC_API_KEY="your key"
export ANTHROPIC_BASE_URL="the address provided by the third party"
```

After saving, run `source ~/.zshrc` to apply it.

**Method 3: Project-level configuration**

Manage this with a `.env` file inside the project directory (paired with the project's own loading mechanism). This suits scenarios where "different projects use different keys," and will be covered in detail in Chapter 2's workspace management section.

> ⚠️ Ironclad safety rule: `.env` files and any file containing keys **must** be added to `.gitignore` — never commit them to a Git repository, and never let a full key show up in a shared screenshot.

### 4. Configuration on the Claude Desktop Side

The Desktop client usually provides an entry point for custom API endpoints within a "Settings → Developer / Model" related panel (the exact name of this entry point may change between versions — the instructor should verify the current interface path before class and record up-to-date screenshots). The core still comes down to two items:

1. A custom API Base URL;
2. A custom API Key.

After configuring, start a new conversation to verify it took effect (for example, asking "what model are you currently using" as a simple check — note that the model may not accurately self-report, so treat this only as a reference).

### 5. Five Principles of Key Security

1. **Never hard-code a key into a file that might get shared** (code, notes, screenshots);
2. **Use different keys for different projects where possible**, so you can revoke individual ones if something goes wrong;
3. **Regularly check usage on the provider's dashboard** — an unusual spike may indicate a leaked key;
4. **The moment you suspect a key has leaked, revoke it immediately on the dashboard and regenerate a new one**;
5. **On public/shared computers, clear your environment variables or log out promptly after use**.

## Frequently Asked Questions

**Q: Are third-party relays cheaper but less secure?**
A: Price and security are two independent dimensions, and you can't equate one with the other — though there is admittedly some correlation between "cheaper" and "less compliance rigor." For enterprise-level scenarios or ones involving customer data, it's advisable to prioritize an official direct connection or a provider with clear compliance credentials.

**Q: What happens if I misconfigure it?**
A: You'll typically get a clear authentication failure or network error message — it won't "silently use the wrong model." Feel free to experiment; you can always switch back to the official configuration to recover.
