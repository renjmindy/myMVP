# 1.7｜Claude Desktop Third-Party LLM API Configuration Tutorial

## Learning Objectives

- Independently complete the full third-party API configuration process for the Claude Desktop client;
- Be able to verify whether a configuration has taken effect, and troubleshoot common configuration failures;
- Round out this chapter's safety thread: compile a personal "safe usage checklist."

## Suggested Duration

20 minutes (step-by-step hands-on)

## Prerequisite Knowledge

- Have completed 1.4, and understand the basic principles of base_url / api_key.

## Course Outline

### 1. How This Lesson Differs from 1.4

1.4 covered "the underlying principles + CLI-side configuration." This lesson focuses on the complete hands-on process for the "Desktop graphical interface," walking students step by step through the entire configuration flow in the desktop client, and running through troubleshooting drills.

### 2. Preparation Before Configuring

- [ ] You have obtained an API Key and Base URL (or equivalent access credentials) from your target provider;
- [ ] You have read that provider's terms of service and understand its data usage and privacy policy;
- [ ] You have confirmed whether that provider supports the model version you need.

> Instructor note: when demonstrating live, use a **test/sample key** or redact it — don't expose a real key in a screen recording or livestream.

### 3. Graphical Interface Configuration Steps (based on the current version — the instructor should verify the screenshots before class)

1. Open Claude Desktop and go to "Settings";
2. Find the "Developer" or "Model / API Configuration" tab;
3. Find the custom endpoint (Custom API Endpoint / Base URL) input field, and enter the address provided by the service provider;
4. Find the API Key input field and paste in the key (remind students to check that the clipboard doesn't contain extra spaces or line breaks before pasting);
5. Save the configuration — there is usually a "Test Connection" button; click it to verify;
6. Start a new conversation and send a simple message to verify that it responds normally.

### 4. Verifying That the Configuration Has Actually Taken Effect

- Observe whether the response speed and style are noticeably different from before (for reference only, not a definitive judgment);
- Some clients display the currently active endpoint address on the settings page, which you can check directly;
- If the provider offers a usage dashboard, send a test message and then check the dashboard for a matching call record — this is the most reliable way to verify.

### 5. Common Troubleshooting

| Symptom | Possible Cause | How to Troubleshoot |
|---|---|---|
| Authentication failure message | API Key is incorrect or has expired | Re-copy the key, check for extra spaces |
| Spinner never resolves, no response | Base URL is entered incorrectly, or the provider's service is down | Check the URL spelling, contact the provider to confirm service status |
| Network error | Local network restrictions/firewall blocking | Check whether a proxy needs to be configured, or switch to a different network |
| Response content is abnormal/doesn't match expectations | The provider's model version doesn't match what was expected | Check the provider's documentation to confirm the exact model being used |

### 6. Wrapping Up This Chapter's Safety Thread: Compile Your Checklist

Looking back across 1.1–1.7, help students consolidate the safety points scattered across each lesson into one actionable checklist:

**Safe Usage Checklist (example — encourage students to personalize it)**

- [ ] Keys are not hard-coded into files/screenshots that might get shared;
- [ ] Different projects use different keys, so any one can be revoked individually;
- [ ] Operations involving deletion, overwriting, or sending data externally default to "Ask mode" rather than auto-accept;
- [ ] For important/production tasks, review the execution plan in Plan Mode before letting it proceed;
- [ ] Have read at least a summary of the third-party provider's data privacy policy;
- [ ] Regularly check key usage, and revoke/reset promptly if anything looks abnormal;
- [ ] `.env` and other key-related files have been added to `.gitignore`.

## Frequently Asked Questions

**Q: Once a third-party API is configured, can it completely replace the official one?**
A: Functionally, possibly — but keep in mind that model version update speed, service stability, and privacy compliance may all differ from the official offering. It's advisable to prioritize an official direct connection for critical tasks, and use a third party for everyday lightweight tasks as appropriate.

**Q: I finished configuring it and the results don't seem right — how do I quickly switch back to the official setup?**
A: Clear/delete the custom endpoint configuration, or change the environment variables back to the official defaults using the method from 1.4. The two access methods don't interfere with each other and can be switched at any time.
