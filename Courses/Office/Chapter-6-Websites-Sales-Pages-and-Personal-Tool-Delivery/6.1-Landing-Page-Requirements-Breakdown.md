# 6.1｜Landing Page Requirements Breakdown: From Idea to Actionable Brief

## Learning Objectives

- Understand why "just have AI make me a website" often produces disappointing results, and that the root cause lies in unclear requirements;
- Master the method of breaking down a vague idea into a structured brief;
- Complete a landing page requirements document that can be handed directly to Claude Code for execution, serving as a common prerequisite step for the hands-on sessions in 6.2–6.4.

## Suggested Duration

25 minutes

## Prerequisite Knowledge

- Completed Chapter 3 (personal content context, visual design system) — this lesson will directly reuse these two assets.

## Course Outline

### I. Why "Help Me Make a Website" Isn't Enough

- Revisit the principle learned in Chapter 1 that "clear instructions beat vague instructions" (covered in detail in 2.6) — landing page development is a classic application of this principle;
- A website involves many decision points: who is the target audience, what is the core selling point, how should the page structure be organized, what should the visual style be, and is there a conversion goal (lead capture / purchase / follow)? If none of this is clear when the task is assigned, the AI can only produce a "generic template" result.

### II. The Core Structure of a Landing Page Brief

Give learners a ready-to-use brief template:

```markdown
# Landing Page Requirements Brief

## 1. Goals and Audience
- What is the core goal of this page? (Brand showcase / Lead generation / Direct sales / Traffic and follows)
- Who is the target audience? (Reuse the audience persona from the personal content context in Chapter 3)

## 2. Core Selling Point
- State it in one sentence: "After viewing this page, what is the one thing the user should remember?"
- 2–3 supporting arguments/highlights for this selling point

## 3. Page Structure
- Which sections should be included? (Hero headline / Pain-point resonance / Solution introduction / Case studies & testimonials / Pricing / FAQ / Call-to-action button, etc., add or remove as needed)
- What is the core message of each section?

## 4. Visual and Brand
- Directly reference the `docs/Visual-Design-System.md` produced in Chapter 3
- Are there any logo/brand assets that must be used

## 5. Conversion Goal and Call-to-Action (CTA)
- What do you want users to do after viewing the page? (Fill out a form, click to purchase, add a contact method)
- Initial ideas for CTA button copy

## 6. Reference Examples (Optional)
- Are there any similar pages you admire? Explain which aspect you like about them (not to copy, but to extract points of inspiration)
```

### III. Hands-On: Using Claude Code to Help Fill Out the Brief

Even at the "organizing requirements" stage, you can let Claude assist and speed things up rather than writing everything by hand:

```
> I want to make a landing page for my [content/product], please combine the content from
> @docs/Personal-Content-Context.md and @docs/Visual-Design-System.md to help me draft
> a first version of the Landing Page Requirements Brief, organized into five sections:
> "Goals and Audience, Core Selling Point, Page Structure, Visual and Brand, Conversion Goal."
> I will revise and confirm based on this draft.
```

Review the generated draft point by point and confirm/correct it — the quality of this vetting step directly determines the effectiveness of the actual development work in 6.2–6.4.

### IV. Common Pitfalls in Requirements Breakdown

- **Pitfall 1: Focusing only on "does it look good" while ignoring the conversion goal** — always be clear on "what you want the user to do after viewing the page" before discussing visuals;
- **Pitfall 2: Piling on too many sections** — more sections don't make a page more complete. For every section added, ask "does this section serve the core selling point?";
- **Pitfall 3: Skipping the audience persona** — different audiences have completely different preferences for "professional and rigorous" versus "friendly and casual." Discussing style without reference to the audience easily results in a page that fits nobody.

### V. Self-Check Checklist After Completing the Brief

- [ ] Can the core selling point be stated in one sentence;
- [ ] Can you explain why each page section exists;
- [ ] Are the visual guidelines already clear (rather than deciding colors and fonts on the fly during development);
- [ ] Are the conversion goal and CTA copy clear.

## Frequently Asked Questions

**Q: Does the brief have to be this detailed? Can it be simplified?**
A: The level of detail can be adjusted based on project complexity, but "target audience, core selling point, and conversion goal" are the minimum items that cannot be omitted — these three determine whether the page is substantive. The rest can be refined progressively during development.

**Q: What if I discover a problem with the brief halfway through?**
A: The brief is not an unchangeable contract — it's a record of your "current best understanding." If you discover an issue during development, go back and adjust the brief and continue. This is a normal part of the iterative process.
