# 6.2｜Personal Brand Website Workflow for Content Creators

## Learning Objectives

- Master the complete workflow of using Claude Code to go from a brief to an actual webpage;
- Complete the development and local preview of a personal brand website page for a content creator;
- Understand how to continuously check for consistency against the content/visual assets from Chapter 3 during development.

## Suggested Duration

35 minutes (In-depth Hands-on)

## Prerequisite Knowledge

- Completed 6.1 (already have a Landing Page Brief); completed Chapter 3 (content context and visual design system).

## Course Outline

### I. Typical Sections of a Personal Brand Website

In the context of content creation, give learners a reference list of sections (corresponding to the "Page Structure" part of the 6.1 Brief):

- Hero section: personal image + one-sentence positioning statement;
- About Me: background story, professional background, account positioning;
- Featured Content: showcase of representative works/article collections;
- Stats/Achievements showcase (optional): follower count, representative case studies, media coverage, etc.;
- Contact information/social account links;
- (Optional) Subscription/collaboration inquiry entry point.

### II. Hands-On: From Brief to First-Draft Page

**Step 1: Hand the Brief to Claude Code**

```
> Based on the requirements in @docs/LandingPageBrief.md, please help me build a personal
> brand website homepage using HTML/CSS, strictly following the color and font guidelines
> in @docs/Visual-Design-System.md. First complete the hero section and the "About Me"
> section, then start a local preview so I can check the result.
```

**Step 2: Local Preview and Review**

- Guide learners to open the local preview in a browser and check it item by item against the Brief: is the core selling point prominent, does the visual match the guidelines, and does the copy's tone match the personal content context from Chapter 3;
- This step echoes the philosophy of the course's `run` skill — after making a change, you must actually run it and see the result, not just look at the code.

**Step 3: Iteratively Complete Section by Section**

Following the section list in the Brief, add the remaining sections one at a time, previewing and confirming after each one, rather than piling everything on at once and troubleshooting afterward.

```
> The hero and About Me sections look great. Now please continue with the "Featured
> Content" section, showcasing these three representative works: [Title 1], [Title 2],
> [Title 3], each with a one-sentence description.
```

### III. Content and Visual Consistency Check (Key Step)

After completing the first draft, run a dedicated round of consistency review:

```
> Please compare the current page against @docs/Personal-Content-Context.md and
> @docs/Visual-Design-System.md, check whether the copy tone and visual presentation
> deviate from the guidelines anywhere, and list what needs to be adjusted.
```

This step has the AI perform a "self-check" in reverse, which is more efficient than manually cross-checking word by word — the human only needs to review whether the AI's proposed list of adjustments is reasonable.

### IV. Responsive Design and Detail Polishing

- Remind learners to check how the page displays across different screen sizes (phone/tablet/desktop), since many visitors will access it via mobile;
- Polish the details: whether images have appropriate loading effects, button click feedback, page load speed, etc. — these details together determine the perceived professionalism.

```
> Please check how the page displays at mobile screen widths, and if there's any
> broken/misaligned layout, help me fix it.
```

### V. Preparing for Delivery (Leading into 6.5)

What's completed in this lesson is a "locally previewable" version. Actually publishing it to the public requires deployment, which will be covered comprehensively in 6.5 "Moving to the Cloud." This lesson focuses on polishing the page content and effects.

## Frequently Asked Questions

**Q: I don't understand HTML/CSS — can I still understand the page code Claude produces?**
A: You don't need to understand the code details. The core approach is to drive iteration through "previewing the result + describing the desired adjustments in natural language" — this is also the core advantage of Claude Code over traditional website-building methods: replacing hand-written code with conversation.

**Q: What if the page I made ends up looking like everyone else's site?**
A: Go back to the personal content context and visual system from Chapter 3 — as long as you strictly develop based on your own real material and guidelines, the output will naturally carry your personal characteristics. "Looking generic" usually happens because the Brief and asset-reuse steps were skipped, and the AI was given a vague description to "just make something."
