## Course Outline

### I. Revisiting the Limitation Left by 5.6

- The cron / task scheduler tools learned in 5.6 depend on your computer being powered on and connected to the internet in order to trigger properly;
- If you want your scripts/website to truly be "accessible at any time, with scheduled tasks running reliably, unaffected by the state of your personal computer," you need to deploy them to the cloud;
- This lesson uses Vercel as an example (a cloud platform that's friendly to individual developers with a simple deployment process) to explain both website deployment and cloud-based scheduled tasks.

### II. Part One: Deploying a Webpage to Vercel

**Step 1: Prepare an Account**

- Sign up for a Vercel account (you can usually log in directly with a GitHub account).

**Step 2: Have Claude Code Help Prepare for Deployment**

```
> I want to deploy the website page I made in the @6.2 lesson to Vercel. Please help me
> check whether the project structure meets deployment requirements, and add any
> necessary configuration files if needed.
```

**Step 3: Execute the Deployment**

- There are generally two approaches: deploying via the Vercel CLI from the command line, or pushing the code to GitHub and linking the repository in the Vercel dashboard for automatic deployment;
- Demonstrate the CLI approach live (which fits better with the Claude Code way of working):

```bash
npx vercel
```

Follow the prompts to complete login confirmation, project linking, and other steps.

**Step 4: Verify It's Live**

After deployment, you'll get a publicly accessible URL. Open it live on both a phone and a computer to verify the result, confirming that this is truly a "anyone can access it" live state — remind learners that this is a public-facing action, so the content should be thoroughly checked before deployment (echoing the consistency-check steps from 6.2–6.4).

### III. Part Two: Configuring a Vercel Cron Scheduled Task

**Step 1: Understand the Basic Principle of Vercel Cron**

- Vercel Cron lets you define an endpoint (a Serverless Function) that's automatically triggered on a schedule, running in Vercel's cloud environment, independent of whether your personal computer is powered on;
- This means the script logic written in 5.1 and 5.6 needs to be wrapped into an endpoint form that the cloud can call on a schedule.

**Step 2: Have Claude Code Help Refactor the Script**

```
> The automation script I wrote in 5.6 currently runs locally. Please help me refactor
> it into a form suitable for deployment as a Vercel Serverless Function, and configure
> the corresponding Cron trigger rule — for example, to run automatically every day at
> 8 AM.
```

**Step 3: Configuration File and Deployment**

- Learn the basic structure of the scheduled-task configuration file in a Vercel project (instructors should verify the current Vercel platform's specific configuration method before class, since platform features may have been updated since);
- After deployment, you can view the Cron task's execution history in the Vercel dashboard.

**Step 4: Verification and Monitoring**

```
> Please help me confirm how to view this Cron task's execution logs in the Vercel
> dashboard after it's successfully deployed, to confirm whether it's triggering
> correctly at the expected time.
```

- Emphasize: cloud scheduled tasks also require the habit of **logging + periodic spot-checks** (echoing the safety principles from 5.6 and 5.7) — deployment isn't a "set it and forget it" action.

### IV. Cloud Deployment Security and Cost Reminders

- Going live means your code and execution logic are exposed publicly — make sure you haven't hard-coded any sensitive information such as API keys into the code (echoing the key-management principles from 1.4 and 5.5; cloud environment variables should be configured through Vercel's environment variables feature in the dashboard);
- Understand whether your chosen cloud platform's plan has free-tier limits — plan the execution frequency and resource consumption of scheduled tasks within your budget to avoid unexpected charges;
- For scheduled tasks that handle user data, make sure they comply with data privacy requirements.

## Frequently Asked Questions

**Q: Do I have to use Vercel?**
A: Vercel is a good fit for individual developers and aligns well with this course's "build and deploy quickly with Claude Code" workflow, but it's not the only option. Other cloud platforms (such as Netlify, or various cloud providers' function-computing services) offer similar capabilities, and the underlying principles are the same. Learners can choose based on their own needs — this course uses Vercel as the teaching example.

**Q: What if I want to change the content after deployment?**
A: Modify the source code and re-run the deployment command (or push to the linked GitHub repository to trigger automatic deployment) to update the live version — there's no need to reconfigure the entire project.
