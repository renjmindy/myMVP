# 5.1 | From Conversation to Script: Letting Claude Code Help You Build Your First Automation Tool

## Learning Objectives

- Understand the essential difference between "conversational use" and "automated scripts";
- Master the basic approach for turning a recurring task into a script;
- Have Claude Code help you write, test, and run your first small automation tool from scratch.

## Suggested Duration

30 minutes (hands-on walkthrough)

## Prerequisites

- Have completed Chapters 1 and 2, and can proficiently use the CLI and basic commands.

## Course Outline

### I. From "Asking Every Time" to "Write Once, Run Countless Times"

- Review the usage pattern from previous chapters: you're present, you issue a task each time, and Claude executes it;
- Pain point: if this is a task you need to do repeatedly (daily/weekly) — such as "organizing the downloads folder every day" or "compiling data every week" — starting a fresh conversation to issue instructions each time is inefficient;
- Solution: have Claude Code **write a script** that locks in the fixed processing logic. Afterward, you only need to run this script (or even have it run automatically on a schedule, as detailed in 5.6), without needing to start a new conversation each time.

### II. What Kinds of Tasks Are Suitable for Scripting

Give learners a set of criteria to check:

- [ ] The task logic is relatively fixed and doesn't require subjective judgment each time;
- [ ] The task recurs (daily/weekly/triggered by a certain condition each time);
- [ ] The task's input and output formats are fairly stable.

Counterexample: tasks requiring a great deal of subjective judgment or creativity (such as "write a creative piece of copy") are not suitable for full scripting, and are better suited to conversational collaboration (the scenarios from Chapters 3 and 4).

### III. Hands-On: Building Your First Automation Tool

Use a concrete, everyday task as an example: "automatically organize the downloads folder by sorting files into categories by file type."

**Step 1: Validate the logic conversationally first**

First, manually run through this once using ordinary conversation (as learned in 4.4) to confirm the sorting logic is what you want.

**Step 2: Ask Claude to turn this logic into a script**

```
> The method we just used to manually organize the downloads folder worked well. Please turn this logic
> into a Python script, with the following requirements:
> 1. Automatically identify files in the ~/Downloads directory
> 2. Sort and move files into corresponding subfolders by file type (documents/images/archives/other)
> 3. Print logs during processing so I can understand what actions were taken
> 4. For files whose type can't be determined, skip them and note it in the log — don't error out and stop
```

**Step 3: Test the script**

```
> Please first simulate running this script in a test folder so I can confirm it works correctly
> before applying it to my actual downloads folder
```

**Step 4: Actual execution and review**

Run the script, check whether the log output and actual sorting results match expectations, and give timely feedback to Claude for any adjustments needed.

### IV. Script vs. Conversation: Discussing the Boundaries of Capability

Class discussion: "Will this script still need you to open Claude Code to run it in the future?"

Guide the discussion toward this conclusion: once a script is written, it can in principle be run directly using the system's own means (without depending on Claude Code itself). This sets up 5.6's "scheduled automation" — a script can run entirely independently of AI conversation. The AI is just the "craftsman who built the tool"; once the tool is built, it can work on its own.

### V. Maintenance and Iteration

- Emphasize that a script isn't something you write once and then ignore — when new edge cases arise (such as a file type the script didn't anticipate), simply go back to Claude to iterate and update it;
- Recommend saving the script together with its corresponding requirements documentation in the project's `scripts/` directory, forming a sustainably maintainable toolkit of automation tools.

## Frequently Asked Questions

**Q: I don't know how to code — can I understand the scripts Claude writes?**
A: You're not required to be able to write code independently, but it's good practice to develop the habit of "asking Claude to explain key logic with comments" and "validating in a test environment before running." It's fine if you don't understand the specific code — the important thing is understanding whether the inputs, outputs, and overall logic match your expectations.

**Q: What should I do if the script errors out when run?**
A: Copy the complete error message to Claude and let it help diagnose and fix the issue — this is itself one of Claude Code's core capabilities, and you don't need to troubleshoot the underlying code yourself.

## Homework

Choose one real recurring task of your own, and go through the entire process of "validate logic conversationally → turn into a script → test → run for real," producing a usable automation script saved in the project's `scripts/` directory.
