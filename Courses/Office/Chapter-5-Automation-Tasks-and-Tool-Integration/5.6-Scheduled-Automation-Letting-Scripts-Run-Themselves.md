# 5.6 | Scheduled Automation: Letting Scripts Run Themselves

## Learning Objectives

- Understand the basic principle of scheduled automation: having a script run automatically on a schedule without supervision;
- Master the basic methods for configuring scheduled tasks on macOS / Windows / Linux;
- Complete scheduling configuration for a real script and verify it runs automatically;
- Build security awareness around the risks of scheduled automation, laying the groundwork for the 5.7 Hooks lesson.

## Suggested Duration

25 minutes (hands-on walkthrough)

## Prerequisites

- Have completed 5.1, and already have at least one usable automation script.

## Course Outline

### I. From "Manually Running a Script" to "the Script Runs Itself"

- Review 5.1: you've already learned to have Claude help you write an automation script, but you currently still need to manually run it in the terminal;
- The goal of this lesson: have this script run automatically on a set schedule (daily, weekly, hourly), so you no longer need to remember to trigger it manually.

### II. Scheduled Task Tools for Different Systems

| System | Common Tool | Description |
|---|---|---|
| macOS / Linux | `cron` | The classic Unix-like scheduled task tool, configured via crontab |
| Windows | Task Scheduler | Graphical interface for configuring scheduled tasks |
| Cloud / deployment environments | The platform's built-in scheduling capability (such as Vercel Cron) | Chapter 6 will cover in detail how to "move a script to the cloud" to run — this lesson focuses on the local-machine level |

### III. Hands-On: Using Claude Code to Help Configure a cron Scheduled Task (macOS / Linux)

**Step 1: Have Claude generate the cron configuration for you**

```
> I have a script scripts/organize_downloads.py that I'd like to run automatically every day at 8 AM.
> Please help me write the corresponding crontab configuration and explain how to add it to the system
```

**Step 2: Understand the cron expression (a basic familiarity is enough — you're not required to write one by hand)**

```
0 8 * * * python3 /full/path/organize_downloads.py
```

Walk learners through recognizing that these five fields roughly correspond to "minute, hour, day, month, weekday." Learners are not required to independently write complex expressions without AI assistance — understanding the gist and being able to read what the AI generates is sufficient.

**Step 3: Add and verify**

```bash
crontab -e
```

Paste in the configuration and save. You can then use a shorter test interval (such as "every 2 minutes") to first verify the script is actually triggered correctly, and once confirmed, change it back to the actual desired frequency.

### IV. Hands-On: Windows Task Scheduler (Brief Walkthrough)

1. Open "Task Scheduler";
2. Create a basic task and set the trigger condition (daily/weekly, etc.);
3. Set the action to "start a program," pointing to the script's execution command;
4. Save and manually trigger it once to verify the result.

(Instructors should record a complete Windows-side walkthrough video before class as a supplementary resource — in class, just briefly walk through the process to avoid using up too much class time.)

### V. Security Reminders for Scheduled Automation (Important)

- A scheduled task means **unsupervised execution** — once the logic has an error, it may fail repeatedly without anyone noticing right away. Be sure to:
  - Build detailed logging into the script to make later troubleshooting easier;
  - For scheduled tasks involving data modification/deletion, put them through a thorough period of manual testing first, and only enable scheduling once stability is confirmed;
  - Periodically (such as weekly) spot-check the execution logs of scheduled tasks, rather than configuring them once and never checking again;
- This is also why 5.7 specifically covers Hooks — to preserve necessary process controllability and the ability to intervene, even as execution is automated.

## Frequently Asked Questions

**Q: Will a scheduled task still run when the computer is turned off?**
A: A local `cron` / Task Scheduler task depends on the computer being powered on. If you need "24/7" reliable execution, you'll need to consider the cloud deployment approach covered in Chapter 6 (such as Vercel Cron).

**Q: If I misconfigure a scheduled task, will it keep failing repeatedly without anyone noticing?**
A: This is exactly why this lesson emphasizes "detailed logging + periodic spot-checks." It's recommended to additionally configure execution-result notifications for key scheduled tasks (such as an email/message alert on failure) — Chapter 6 will introduce a more complete cloud monitoring solution.

## Homework

Configure the automation script you completed in 5.1 as a scheduled task. First test with a short interval to verify it triggers correctly, then adjust it to the actual frequency you need, and check the logs after at least one full cycle has run.
