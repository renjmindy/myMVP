# 5.9 | Hands-On: Automated Video Content Pipeline (Script → Voiceover → Short-Form Video)

> After this lesson, shipping one short-form video no longer means doing every step yourself.

## Learning Objectives

- Apply the assembly pattern learned in 5.1–5.8 (script it → connect external capabilities → schedule it → keep it controllable with Hooks) to a second, very different domain: short-form video production;
- Independently build a pipeline that takes a single topic and produces a script, an AI voiceover, subtitles, and an edited short video, ready for review before publishing to YouTube/Instagram;
- Understand why a creative-content pipeline needs a different shape of human checkpoint than a data-reporting pipeline (5.8), and where exactly that checkpoint belongs.

## Suggested Duration

35 minutes (hands-on walkthrough)

## Prerequisites

- Have completed 5.1–5.8 — this lesson introduces no fundamentally new automation concepts, it recombines them in a new domain;
- Helpful but not required: 3.1 (personal content context) and 3.3 (market research for content opportunities), which supply the raw material for the topic-selection step below.

## The Pipeline at a Glance

Every solo creator hits the same wall: for a single video, you're personally responsible for scripting, recording or generating narration, cutting the footage, adding captions, and uploading — the whole chain runs through you, one step at a time. That's the same shape of problem 5.8 solved for data reporting, applied to a different set of tools.

Seven modules, each mapped to a lesson you already know:

- **5.9-1 Topic → Script** — maps to 5.1, plus 3.1/3.3 if completed
- **5.9-2 Script → AI Voiceover** — maps to 5.2–5.5 (MCP / external service connections)
- **5.9-3 Voiceover/Script → Subtitles** — maps to 5.2–5.5
- **5.9-4 Script + Voiceover + Subtitles → Edited Short Video** — maps to 5.5
- **5.9-5 Human Review Checkpoint** — maps to 5.7 (Hooks), but as a quality gate, not just an error check
- **5.9-6 Scheduled/Batch Production** (optional) — maps to 5.6
- **5.9-7 Publish to YouTube/Instagram (draft/unlisted only)** — new

> One key difference from 5.8, up front: a daily report is internal and factual, so 5.8's safety check only needs to catch missing or broken data. A published video is public-facing brand content, so this pipeline needs a genuine **human review checkpoint** at 5.9-5 — not an anomaly check that can wave things through.

## Build It: 7 Steps, Each With a Checkpoint

### 5.9-1　Topic → Script (reusing 5.1, and 3.1/3.3 if completed)

Before you ask Claude to write, pick which of the 4 opening patterns fits your topic — the pattern you choose changes what the first 3 seconds need to do:

| Pattern | Opens with | Best for |
|---|---|---|
| **Direct-Question** | The exact question your viewer is already silently asking | Topics where the audience already knows they have the problem |
| **Immediate-Demo** | The result or technique shown first, explained after | Visual/technical topics where seeing beats hearing |
| **Myth-Correction** | Naming a common mistake or misconception | Topics where the audience thinks they're already doing it right |
| **Before/After** | A contrast between two states, shown before any explanation | Topics with a clear transformation to show |

Generic 60-second shape, regardless of pattern: **0–3s opening move → 3–15s why this matters / what's really going on → 15–45s the point(s), demonstrated or explained → 45–60s closing CTA.**

✏️ Copy and paste to Claude:

```
I want to turn a single topic into a short-form video script. Given the topic
[your topic, e.g., "3 mistakes people make with X"], and using the [Direct-Question /
Immediate-Demo / Myth-Correction / Before-After] opening pattern, please help me write
a script for a 60-second video: opening (first 3 seconds), 2-3 key points, and a
closing call to action. Keep the tone consistent with [your personal content context,
if you have one from 3.1]
```

✅ **Checkpoint**: You have a structured 60-second script — an opening that matches your chosen pattern, 2–3 key points, closing CTA.

### 5.9-2　Script → AI Voiceover (reusing 5.2–5.5)

✏️ Copy and paste to Claude:

```
Please help me check whether there's an MCP Server or API available for text-to-speech
generation that I can connect to directly. If so, help me write a script that sends
the script from Step 1 to that service and saves the resulting audio file locally.
If there isn't a ready-made MCP Server, help me write a connection script using the
method learned in 5.5
```

💡 Text-to-speech quality and availability aren't uniform across services — verify what's actually available to you at build time, rather than assuming a specific tool.

✅ **Checkpoint**: You have a narration audio file generated from your script, saved locally.

### 5.9-3　Voiceover/Script → Subtitles (reusing 5.2–5.5)

✏️ Copy and paste to Claude:

```
Please help me connect to a transcription or subtitle-generation service (via MCP or
API) that takes the voiceover audio and script from the previous steps and produces
a timed subtitle file (e.g., .srt), so the captions stay in sync with the narration
```

💡 Subtitle-generation accuracy varies by service — spot-check the timing against the audio before moving on.

✅ **Checkpoint**: You have a timed subtitle file that stays in sync with the narration.

### 5.9-4　Assemble the Short Video (reusing 5.5)

✏️ Copy and paste to Claude:

```
I have a script, a voiceover audio file, a subtitle file, and [my visual assets /
a stock footage source]. Please help me write a script that drives [my video-editing
tool or API] to combine these into a single short-form video file, with the subtitles
burned in or attached as a caption track
```

✅ **Checkpoint**: You have one video file with narration, visuals, and captions combined.

> 💡 No video-editing API or MCP Server available yet? Build as much of the pipeline as your tools allow (script, voiceover, and subtitles are the easiest to fully automate), and do this step by hand for now — a partially automated pipeline still saves real time.

### 5.9-5　Add a Human Review Checkpoint (reusing 5.7 — read the callout below before configuring)

✏️ Copy and paste to Claude:

```
Please help me configure a Hook that runs after the video is assembled but before any
publish/upload step: it should stop the pipeline, notify me that a draft is ready for
review, and require my explicit confirmation before continuing — do not let this step
auto-approve under any condition
```

✅ **Checkpoint**: Run the pipeline once, all the way to this step, and confirm it actually pauses and waits for your explicit approval — don't just assume the Hook is configured correctly.

> 💡 **This gate is non-negotiable, unlike 5.8's anomaly check.** It should stop the pipeline every single time and wait for a human decision — not just on unusual cases. A published video is public brand content: a wrong claim, an off-brand tone, or a rights issue with a voice or face is far more costly to walk back than a daily report with a formatting glitch.

### 5.9-6　(Optional) Schedule Batch Draft Production (reusing 5.6)

✏️ Copy and paste to Claude:

```
Please help me configure this pipeline, from topic input through Step 4, to run on a
recurring schedule against a queue of topics I provide, so that draft videos are
waiting for my review each time I sit down, rather than me starting the pipeline
manually every time
```

✅ **Checkpoint**: A queue of topics produces draft videos on a recurring schedule, waiting for review.

> 💡 Like 5.8, this still depends on your computer being on. Truly device-independent execution requires the cloud-deployment approach in Section 6.5 of Chapter 6.

### 5.9-7　Publish to YouTube/Instagram (new, draft/unlisted only)

✏️ Copy and paste to Claude:

```
Please help me connect to the YouTube/Instagram upload API (or an available MCP Server)
and write a script that uploads the reviewed, approved video as a draft or unlisted
post — not a public, immediate publish — so a final manual step is still required
before it goes live
```

✅ **Checkpoint**: The approved video lands as a draft/unlisted upload — never a live, public post straight from the pipeline.

> 💡 Upload-API access levels differ by platform and account, and change over time. Treat this step as a pattern to adapt, not a guaranteed off-the-shelf integration — verify what's actually accessible when you build this.

## Frequently Asked Questions

**Q: Do I need professional video-editing skills to build this?**
A: No — you need to understand each step well enough to review its output, since you're wiring together existing services rather than editing manually. But you do still need working knowledge of whatever editing tool or API sits in 5.9-4; this lesson doesn't remove that requirement, it removes the need to operate that tool by hand for every single video.

**Q: Why not just let the whole thing run end-to-end with no human step, the way 5.8's daily report does?**
A: Because the cost of a mistake is different. A daily report that goes out with a minor formatting issue is a minor annoyance; a video published to a public channel with a factual error, an off-brand tone, or a voice/likeness issue is much harder to undo once it's live. Keep 5.9-5's review checkpoint non-negotiable, and keep 5.9-7 uploading as a draft rather than a live publish.

**Q: What if I don't have access to a video-editing API or MCP Server?**
A: Build as much of the pipeline as your available tools allow (script, voiceover, and subtitles are the easiest to fully automate), and treat 5.9-4 as a manual step for now. The point of this lesson is practicing the "chain several automated steps together, with a review gate before anything public" pattern — a partially automated pipeline still saves real time.

## Chapter 5 Summary

Chapter 5 represents the highest technical bar in the entire course. Upon completion, learners should now possess the complete capability to build an automated system: "identify a recurring task → turn it into a script → connect to external capabilities (MCP/custom services) → run automatically on a schedule → preserve controllability with Hooks → assemble it into a complete hands-on system." This capability was validated twice — once against a factual, internal use case (the daily report system in 5.8) and once against a creative, public-facing use case (the video content pipeline in 5.9) — showing that the same assembly pattern holds across very different domains, while the shape of the human checkpoint changes with the stakes involved. Chapter 6 will build on this foundation, further applying these capabilities to the more concrete output scenario of "delivering websites, sales pages, and personal tools," and in 6.5 will close the final piece left open by this chapter — truly "moving the automated system to the cloud" to achieve stable, device-independent 24/7 execution.
