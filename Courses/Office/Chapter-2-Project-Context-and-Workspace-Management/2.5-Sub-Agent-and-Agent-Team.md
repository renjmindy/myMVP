## Course Outline

### I. Why Sub Agent Is Needed

- Pain point: if a complex task is handed entirely to one "generalist," it easily leads to context overload, divided attention, and insufficient specialization;
- Solution: break the task down and assign it to multiple "dedicated sub-agents" to handle separately, each with its own independent context and scope of responsibility, then aggregate the results back to the main agent when done;
- Analogy: a project manager (the main agent) breaks a task down among a "research specialist," a "copywriting specialist," and a "review specialist" (sub-agents), rather than one person juggling all roles non-stop.

### II. The Typical Structure of a Sub Agent

Explain using a real scenario, for example "writing a competitive analysis article":

```
Main task: Write a competitive analysis article
 ├── Sub Agent A: Gather data (focused on information retrieval, not concerned with writing style)
 ├── Sub Agent B: Write the first draft (focused on written expression, based on the data provided by A)
 └── Sub Agent C: Review and proofread (focused on finding errors and logical gaps, not involved in creation)
```

**Core value:**

- Focus: each sub-agent only needs to understand the context relevant to its own part, reducing the problem of "diluted attention";
- Parallelism: some sub-tasks can proceed simultaneously, rather than strictly waiting in line;
- Reusability: sub-agents such as the review/proofreading one can reuse the same responsibility configuration across different projects.

### III. The Difference Between Sub Agent and Agent Team

| Dimension | Sub Agent | Agent Team |
|---|---|---|
| Scale | Usually 1 or a few dedicated assistants temporarily called by the main agent | A group of multiple agents that are pre-configured and may collaborate over the long term |
| Relationship | A master-subordinate relationship; sub-agents serve the main agent's current task | Closer to a "team," possibly with more complex role division and collaboration rules |
| Suitable scenario | Breaking down a single complex task | Long-term, recurring multi-role collaboration workflows (such as a content production pipeline) |

> Instructor tip: the specific feature naming and boundaries will change as Claude Code versions iterate. The instructor needs to verify against the current official documentation before class whether the terminology has been updated. The key takeaway of this lesson is the design philosophy of "dividing responsibilities, specialized collaboration" — the philosophy is more lasting than the specific terminology.

### IV. Hands-on Demonstration: Invoking a Sub Agent to Complete a Collaborative Task

1. Use `/agents` to view the currently available Sub Agent configurations;
2. Demonstrate a real task live, for example:

```
> Help me research the three leading products in the "AI writing tools" space, organize their pricing strategies respectively, and then write a 200-word comparative summary
```

3. Observe whether Claude automatically splits "research" and "summary writing" into different stages, and guide learners to notice the traces of division of labor in the process;

## Frequently Asked Questions

**Q: When should I use Sub Agent, and when should I just let Claude handle it on its own?**
A: Simple, single-dimension tasks don't need to be deliberately split up — let Claude handle them autonomously. When a task clearly involves multiple sub-steps of different natures (research + creation + review) and quality requirements are high, proactively designing a Sub Agent division of labor will be more reliable.

**Q: Will using Sub Agent slow the task down?**
A: Splitting up collaboration may take a few more steps in the process compared to "doing it in one go," but in exchange, each stage is more focused and the results are more reliable. This usually offers a better cost-performance ratio on complex tasks; it's not recommended to over-design this for simple tasks.
