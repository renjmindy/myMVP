# Chapter 2 | Project Context and Workspace Management

## Chapter Positioning

Chapter 1 addressed "getting it installed, feeling comfortable using it, and knowing the basic commands." Chapter 2 addresses a more advanced problem: **how to let Claude Code understand your project background stably and continuously, instead of explaining everything from scratch every time.**

After completing this chapter, learners should be able to:

1. Establish a standardized working folder structure for any project;
2. Write a `CLAUDE.md` so that the AI automatically understands the project background, conventions, and prohibitions before every conversation begins;
3. Understand the division of labor between the Claude Projects workspace and CLAUDE.md, and complete one actual configuration;
4. Use a single map to clarify the relationships among the frequently-appearing but easily-confused core concepts: API, MCP, CLI, Skills, Artifacts, and Projects;
5. Understand the collaboration model between Sub Agent and Agent Team, and know where to find authoritative official resources for continued learning;
6. Build a foundational understanding of the principles behind "workspace management" and "context management," forming several actionable best practices.

This chapter serves as a bridge: the previous chapter taught "how to operate," and this chapter teaches "how to organize," providing a reusable project skeleton for the hands-on project (a content creation system) that begins in Chapter 3.

## Lesson Schedule (Suggested)

| Lesson | Title | Suggested Duration | Format |
|---|---|---|---|
| 2.1 | How to Create a Claude Code Working Folder | 20 minutes | Lecture + Hands-on |
| 2.2 | Claude.md File Configuration: Letting the AI Understand Your Background | 30 minutes | Lecture + In-depth Hands-on |
| 2.3 | Claude Projects Workspace Configuration | 25 minutes | Lecture + Hands-on |
| 2.4 | Core Concepts: API, MCP, CLI, Skills, Artifacts, Projects | 30 minutes | Concept Overview + Diagrams |
| 2.5 | Sub Agent and Agent Team, and the Claude Code Official Learning Guide | 30 minutes | Lecture + Hands-on Demonstration |
| 2.6 | Claude Code Fundamentals and Best Practices | 25 minutes | Lecture + Discussion |

The entire chapter takes approximately 2.5–3 hours in total, and it is recommended to split it across 2–3 class sessions. Lessons 2.1/2.2/2.3 are best taught consecutively (they form a single "workspace setup" thread), while 2.4/2.5/2.6 can be combined into a single "concepts and principles" session.

## Prerequisites for Learners

- Have completed Chapter 1, with the CLI running normally and at least one actual task completed;
- It is recommended to prepare a real (or semi-real) small project as the practice subject for this chapter — for example, "my personal media account materials" or "documentation for a small company product." The entire chapter should build continuously around this single project, avoiding switching scenarios from scratch in every lesson.

## Chapter Deliverables / Success Criteria

After completing this chapter, learners should produce:

- [ ] A well-structured working folder that conforms to the recommended structure in 2.1;
- [ ] A `CLAUDE.md` written for their own real project;
- [ ] At least one fully configured Claude Project, including background materials and custom instructions;
- [ ] The ability to independently draw or verbally describe the relationship diagram of the six concepts: API, MCP, CLI, Skills, Artifacts, and Projects;
- [ ] A completed hands-on demonstration of a Sub Agent collaboration task;
- [ ] The ability to state at least 3 workspace management best practices and explain the reasoning behind them.

## Instructor Tips

- The most common issue in this chapter is that "the concepts are taught too abstractly and learners can't remember them" — for 2.4, make sure to use diagrams/analogies rather than piling up plain text;
- `CLAUDE.md` is the most important deliverable of this chapter; it's recommended to reserve ample time for live writing and feedback rather than doing only a demonstration;
- 2.5 involves links to official documentation — be sure to verify before class that the links are still valid, and remind learners that official documentation is continuously updated, so the content in this course is a snapshot at a particular point in time.
