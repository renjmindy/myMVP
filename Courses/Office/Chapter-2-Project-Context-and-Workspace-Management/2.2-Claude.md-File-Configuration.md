# 2.2 | Claude.md File Configuration: Letting the AI Understand Your Background

## Learning Objectives

- Understand how `CLAUDE.md` works: why writing it allows the AI to "remember" the project background;
- Master the core content structure of `CLAUDE.md`;
- Be able to use `/init` to quickly generate an initial version, then refine it manually;
- Be able to distinguish "content that should go into CLAUDE.md" from "content that shouldn't."

## Suggested Duration

30 minutes (this is a key lesson in this chapter — reserve ample time for hands-on practice and feedback)

## Prerequisites

- Have completed 2.1 and already have a standardized project working folder.

## Course Outline

### I. What Problem Does `CLAUDE.md` Solve

- Pain point review: if you have to re-explain "what this project does, what the coding standards are, what my writing style is" to Claude every time you start a new conversation, it's very inefficient and prone to omissions or inconsistencies;
- Solution: `CLAUDE.md` is a Markdown file placed in the project's root directory. When Claude Code reads this project, it automatically loads its content as background knowledge — equivalent to giving the AI advance "onboarding training";
- Analogy: when a new colleague joins, you give them a "team handbook" instead of repeating everything verbally every day — `CLAUDE.md` is the team handbook you give to the AI.

### II. What Content Should Go Into `CLAUDE.md`

Recommended structure (can be added to or trimmed depending on project type):

```markdown
# Project Name

## Project Overview
A one-sentence description of what this project does, and who/what goal it serves.

## Background and Constraints
- Who the target audience is
- Which standards must be followed (brand tone, formatting requirements, regulatory restrictions, etc.)
- What things are explicitly not allowed

## Workflow and Habits
- How I usually start a task
- Which directory outputs should be placed in
- What the naming conventions are

## Common References
- Where key documents/data sources are located
- What common custom commands are available
```

**Content type distinctions (key teaching point):**

| Type | Suitable for CLAUDE.md? | Reason |
|---|---|---|
| Project background, long-term stable standards | ✅ Suitable | Useful in every conversation; write it once and benefit long-term |
| Team/brand tone and style requirements | ✅ Suitable | Stable, generally applicable across tasks |
| Temporary details for a single task | ❌ Not suitable | Should be explained within that specific conversation, to avoid CLAUDE.md becoming increasingly bloated |
| Keys, passwords, and other sensitive information | ❌ Absolutely not suitable | Security risk, and CLAUDE.md is often committed to version control |

### III. Hands-on: Generate an Initial Version with `/init`

1. Start Claude Code in the project root directory;
2. Type `/init` and observe Claude automatically scan the project files and generate an initial `CLAUDE.md` draft;
3. Open the generated file and walk learners through it section by section: which parts did the AI guess correctly, and which need manual correction/supplementation.

> Instructor tip: what `/init` generates is a "starting draft," not a finished product. Be sure to guide learners to personally fill in information such as "background and constraints" that the AI cannot guess out of thin air.

### IV. Live Writing Exercise

Give learners 10 minutes to hand-write a complete `CLAUDE.md` for the example project they set up in Chapter 1, including at least the three sections "Project Overview, Background and Constraints, Workflow." After finishing:

1. Use `/clear` to start a brand-new conversation (to ensure no old context interferes);
2. Ask Claude: "Based on the current project's CLAUDE.md, please introduce this project's background and the standards you need to follow";
3. Compare and check: does what it repeats back match what you wrote, and did it miss any key constraints?

### V. Maintenance Habits

- `CLAUDE.md` is not something you write once and finish — whenever you notice "the AI made the same kind of mistake again," think about whether the corresponding rule should be added to `CLAUDE.md`;
- In team collaboration settings, `CLAUDE.md` can be committed to version control along with the code, becoming a shared "AI usage standard" for the team.

## Frequently Asked Questions

**Q: Is a longer `CLAUDE.md` always better?**
A: No. An overly long `CLAUDE.md` consumes context space and dilutes key points. The principle is to write only content that is "long-term stable and useful in every conversation," and to explain specific task details within that particular conversation instead.

**Q: Can multiple projects share one `CLAUDE.md`?**
A: It's recommended that each project have its own project-level `CLAUDE.md` to reflect that project's unique background. If there are personal habits that apply across projects, check whether there is a way to use user-level global configuration to hold them (depending on version features — this can be an advanced topic to explore).
