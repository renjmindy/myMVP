# 2.3 | Claude Projects Workspace Configuration

## Learning Objectives

- Understand the positioning of Claude Projects and its division of labor with `CLAUDE.md`;
- Complete the creation of a Project: uploading a knowledge base, setting custom instructions;
- Be able to judge "what content should go into a Project, and what should remain in a single conversation";
- Understand the connection and differences between Projects and the CLI workspace.

## Suggested Duration

25 minutes

## Prerequisites

- Have completed 1.2 (familiarity with the basic Claude Desktop interface) and 2.2 (understanding what CLAUDE.md does).

## Course Outline

### I. Clarifying the Relationship Between Projects and CLAUDE.md (Key Point)

This is where learners most easily get confused, so be sure to explain it clearly:

| Dimension | CLAUDE.md | Claude Projects |
|---|---|---|
| Location | A file within the project folder | A "space" within Claude Desktop / the web app |
| Use case | Primarily serves automation/development-type work in the Claude Code CLI | Primarily serves conversational collaboration in Claude Desktop |
| Content form | A single Markdown file | A knowledge base that can hold multiple files, images, and long-term data |
| Update method | Edit the file directly | Upload/manage files through the interface |
| Essence | A handbook for the "agent" | Memory and background for the "chat space" |

> One-sentence summary: "CLAUDE.md is Code's handbook; Projects is Desktop's memory and background." The two can share content (the same project background, organized separately into forms suited to each medium), but they are not the same thing and cannot substitute for each other.

### II. Hands-on: Create a Claude Project

1. Find the Projects entry point in Claude Desktop and create a new Project;
2. Name it (it's recommended to keep it consistent with the example project used in Chapters 1 and 2, to maintain continuity);
3. Upload background materials: these can be documents, exports of past chat history, or reference materials (corresponding to the file upload operation learned in Chapter 1);
4. Set "Custom Instructions": these are Project-level behavioral constraints, for example "respond in Simplified Chinese, with a tone that is professional but not stiff";
5. Start a new conversation within this Project and test whether it already "knows" the background materials you uploaded.

### III. What Content Is Suitable to Put Into a Project

- Long-term, stable background materials that will be used across many conversations (brand introductions, product manuals, past high-performing case studies);
- Reference documents that need to be consulted frequently but don't need to be re-uploaded every time;
- A team's shared knowledge base (if this is a team-tier feature, mention it as well).

**Content not suitable to put into a Project:**

- One-off, temporary task materials (it's recommended to upload these directly within a single conversation, keeping the Project's knowledge base clean);
- Sensitive information, or unredacted customer data (unless the data handling policy is clearly understood and authorization has been obtained).

### IV. How Projects and the CLI Workspace Work Together

Give learners a practical workflow example to help them understand how the two work in tandem:

> Scenario: you're working on a market research report.
> 1. In a Claude Desktop Project, accumulate industry background materials, competitor information, and past report templates (long-term data);
> 2. Use a Desktop conversation to complete data review, initial analysis, and structural organization (conversational collaboration);
> 3. Export the final outline/key points, and use the Claude Code CLI locally to generate the formal Markdown / data visualization files, with automated formatting and batch processing (engineering implementation).

### V. In-Class Exercise

Have learners complete the following in their own Project:

1. Upload at least 1 piece of real background material;
2. Set 1 custom instruction;
3. Start a new conversation and ask a question to verify whether the Project correctly applied the background material and instruction.

## Frequently Asked Questions

**Q: Will data in a Project be used to train the model?**
A: Data usage policy is governed by Anthropic's latest official terms. It's recommended to guide learners to check the current privacy policy page before formal use, rather than giving specific commitments in class that could become outdated.

**Q: Can one Project correspond to multiple CLAUDE.md projects?**
A: Yes, they can be flexibly matched as needed. For example, a large content brand Project could correspond to several specific Code project folders (different columns/content series). The key is that the granularity of the background materials should match the actual use case.
