# 7.2 | Building a Personal Prompt Template Library: Turning Useful Prompts into Reusable Assets

## Learning Objectives

- Systematically retrieve and organize all effective prompts accumulated across the previous 6 chapters;
- Master the classification system and maintenance methods for a prompt template library;
- Complete a structured, sustainably iterable personal prompt template library.

## Suggested Duration

30 minutes (hands-on deep dive)

## Prerequisite Knowledge

- Have completed Chapter 4, Section 4.8 (the Cowork prompt collection, the direct prerequisite for this lesson); have completed Chapter 1, Section 1.6 (methods for templating custom commands).

## Course Outline

### I. From "Collection" to "Library": This Lesson's Relationship to 4.8

- What 4.8 accomplished was organizing prompts "within the scope of Chapter 4";
- The goal of this lesson is to take all the effective prompts produced through hands-on work across **the entire course, Chapters 1–6**, and consolidate them into a single, uniformly managed "library," covering the full range of scenarios — content creation, office collaboration, automation, sales page development, and more;
- This is the first concrete manifestation of this chapter's positioning of "integration and consolidation."

### II. Classification System for the Prompt Template Library

Give learners a directly applicable classification framework (corresponding to scenarios from each course chapter):

```
docs/Prompt-Template-Library/
  01-Content-Creation.md         # Corresponds to Chapter 3: topic selection, writing, visual descriptions
  02-Office-Collaboration.md     # Corresponds to Chapter 4: file organization, spreadsheet processing, market research
  03-Automation-Development.md   # Corresponds to Chapter 5: script writing, MCP connections
  04-Website-Sales-Pages.md      # Corresponds to Chapter 6: brief breakdown, page development, deployment
  05-General-Efficiency.md       # Cross-scenario general-purpose prompts (e.g., "check consistency," "generate a summary")
```

### III. Hands-On: Systematic Retrieval and Organization

**Step 1: Let Claude Code Assist with Retrieval**

If the outputs from your previous 6 chapters are properly stored within their respective project folders (echoing the workspace management conventions from Chapter 2), you can have Claude directly assist with scanning and organizing:

```
> Please scan the docs directories and .claude/commands directories in these project folders,
> and help me extract all prompt content that has appeared and is clearly structured,
> organizing it into a list under five categories: content creation, office collaboration,
> automation development, website sales pages, and general efficiency
```

**Step 2: Manual Screening and Templating**

- Go through the AI-extracted list item by item: which ones are genuinely useful and worth keeping, and which ones are one-off and don't need to be preserved;
- For the prompts you keep, use the methods learned in 1.6 and 4.8 to mark out replaceable parameters and turn them into general-purpose templates.

**Step 3: Add Metadata**

Add a brief usage note to each template, to make future retrieval and use quick and easy:

```markdown
## [Template Name]
**Applicable Scenario**: A one-sentence description of when to use this
**Template Content**:
[The specific prompt template]
**Usage Example**:
[An actual example with parameters filled in]
```

### IV. Maintenance Habits: Keeping the Library Growing

- It's recommended to build the habit of adding to the relevant category file right away whenever you complete a new type of task with Claude or discover a useful way of phrasing something;
- Periodically (e.g., monthly) review the template library, remove entries that no longer apply, merge similar ones, and refine wording that isn't clear enough — maintaining the library's quality rather than simply piling on volume.

### V. Advanced: From Templates to Custom Commands

- For the templates you use most frequently, formally convert them into custom commands under `.claude/commands/` using the method learned in 1.6, achieving "one-click invocation";
- This step is also the preparation for 7.3, "Packaging into a One-Click Skill" — only once you have well-consolidated prompt templates do you have the raw material needed to package them into a formal Skill.

## Frequently Asked Questions

**Q: How many entries does a prompt library need before it counts as "built"?**
A: There's no absolute number requirement. This chapter recommends at least 15 entries as the minimum standard for graduation assessment, but the real value lies in continuous use and iteration, not one-time padding of numbers.

**Q: If everyone on a team builds their own, isn't that duplicated effort?**
A: A personal template library should start from your own genuine needs. Once mature, you can consider which parts are worth sharing and merging across the team (which are team-wide and which are personal). Methods for sharing resource libraries in team collaboration scenarios will be discussed further in 7.4.
