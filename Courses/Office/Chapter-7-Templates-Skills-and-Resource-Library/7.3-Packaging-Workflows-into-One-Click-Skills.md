# 7.3 | Claude Code Skills: Packaging Workflows into One-Click Skills

## Learning Objectives

- Understand how a Skill represents an advancement over a custom command (1.6): more complete workflow encapsulation capability;
- Master the basic method for packaging a multi-step workflow into a Skill;
- Complete the development and invocation testing of at least one formal Skill.

## Suggested Duration

30 minutes (hands-on deep dive)

## Prerequisite Knowledge

- Have completed 1.6 (custom commands) and 7.2 (the prompt template library); this lesson is an advanced extension of both.

## Course Outline

### I. From Custom Commands to Skills: Where the Capability Upgrade Lies

Revisiting the "capability pyramid" foreshadowed in Chapter 2, Section 2.4, this lesson formally unfolds the topmost level:

| Level | Scope of Capability | Suitable Scenarios |
|---|---|---|
| Custom Command (1.6) | A single prompt template, applied on trigger | Simple, fixed-expression reuse |
| Skill (this lesson) | Complete workflow encapsulation, which can include multi-step logic, reference material, and a description of trigger conditions | Complex, multi-step workflows that need their methodology consolidated |

- Continuing the analogy from 1.6: if a custom command is "a keyboard shortcut you set up yourself," a Skill is "a whole pre-configured professional toolkit that you pull out and use to solve the matter in one go when the right scenario comes up."

### II. What Kind of Workflow Is Worth Packaging into a Skill

Give learners a judgment checklist:

- [ ] This workflow involves multiple steps, with a clear sequential logic between them;
- [ ] This workflow is one you (or your team) will use repeatedly, and you want execution to remain consistent across different occasions;
- [ ] This workflow has accumulated some "best practices" or "things to watch out for" that are worth consolidating, rather than executing from memory each time.

Looking back over the first 6 chapters, many complete workflows are natural candidates for Skills — for example, Chapter 3's complete "market research + benchmark analysis" process, Chapter 4's "spreadsheet data cleaning and aggregation" process, and Chapter 6's "landing page brief to deployment" process.

### III. Hands-On: Packaging a Real Workflow into a Skill

Using the "market research workflow" (echoing Chapter 3, Section 3.3) as an example:

**Step 1: Lay Out the Complete Steps of the Workflow**

Review the research steps learned in 3.3: trend collection → structured organization → identifying opportunities → converting into topic proposals. First, write this process out clearly.

**Step 2: Ask Claude to Help Build the Skill**

```
> I want to package the "market research workflow" into a Skill, triggered when I need
> to research content topics for a given vertical.
> The core steps are:
> 1. Search for recent trending topics in this vertical
> 2. Organize them into a comparison table of topic popularity vs. content supply
> 3. Identify opportunities where content supply is insufficient
> 4. Convert these into concrete, actionable topic suggestions
> Please help me organize this content according to the standard Skill format, including
> a description of the trigger scenario and step-by-step operating instructions
```

**Step 3: Review the Structure of the Generated Skill**

Familiarize learners with the core elements a Skill typically contains:

- A description of the trigger scenario (helping the AI judge "when this Skill should be used");
- Step-by-step operating instructions;
- Reference materials/templates that might be used (this can be linked to the prompt library built in 7.2);
- Notes on caveats/boundaries.

**Step 4: Actual Invocation Testing**

Trigger this Skill with a real research task to check whether it correctly recognizes the scenario and executes according to the expected steps. Go back and adjust the Skill's definition for anything that doesn't work as well as hoped.

### IV. Iterating and Maintaining Skills

- Like the prompt template library, Skills also require continuous iteration — whenever you discover a new edge case or opportunity for improvement during actual use, update the Skill's definition promptly;
- Multiple related Skills can call/chain into one another, forming more complex composite workflows (setting up for 7.6, "Building Your AI Work System").

### V. Sharing and Reusing Skills (Depending on Feature Support)

- Where conditions allow, a well-crafted Skill can be shared with a team or community for reuse — this is also the origin of resource lists like the "50 Must-Have Skills" in 7.1: they are all workflow assets that others have polished and consolidated before sharing.

## Frequently Asked Questions

**Q: What is the relationship between a Skill and MCP (Chapter 5)?**
A: MCP solves the problem of "connecting to external tools/data sources," while a Skill solves the problem of "consolidating and encapsulating a workflow"; a Skill can perfectly well call a tool capability accessed via MCP internally. The two operate at different levels and can work together.

**Q: Do I have to develop a Skill myself, or can I just use one someone else has already made?**
A: Prioritize reusing an existing, well-evaluated Skill from 7.1; only consider developing your own when there genuinely is no ready-made solution and it's a workflow you need repeatedly. This is also why this lesson emphasizes "laying out the steps clearly before you start building" — sharpening the axe saves time cutting the wood.
