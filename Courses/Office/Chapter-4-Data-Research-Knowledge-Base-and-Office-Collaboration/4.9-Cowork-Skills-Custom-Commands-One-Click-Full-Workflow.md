# 4.9 | Cowork Skills Custom Commands: One-Click Full Workflow Trigger

## Learning Objectives

- Understand the positioning of Skills within the Cowork desktop scenario: packaging a whole set of repetitive collaboration workflows into a capability that can be invoked with one click — distinct from the custom commands for Claude Code CLI covered in Chapter 1's 1.6, and also distinct from the formal Skill development for Claude Code covered in Chapter 7's 7.3;
- Understand how Plugins extend the boundary of Cowork's ability to connect with external services;
- Complete the setup of at least one Cowork Skill, and verify the effect of "one shortcut triggers a complete AI workflow."

## Suggested Duration

25 minutes (in-depth hands-on)

## Prerequisites

- Have completed 4.1–4.8, and have already accumulated a set of prompts and collaboration workflows repeatedly used in Cowork (echoing the prompt collection and SOP checklist from 4.8).

## Course Outline

### I. From "Having to Say It All Again Each Time" to "One-Click Trigger"

- Revisit the pain point: even with the prompt collection organized in 4.8, using it each time still requires manually opening, copying, pasting, and adjusting parameters for the scenario — it's still "manually triggered";
- What Skills solve is the "triggering method" problem — packaging a fixed collaboration workflow (which data to open, what steps to follow, what format to produce) into a named capability, so that afterward a short command or even a shortcut key can launch the entire workflow, without needing to redescribe it each time.

### II. The Division of Labor Between Skills and Plugins in the Cowork Scenario

| Concept | Function | Analogy |
|---|---|---|
| Skills | Package "how to do it" — a fixed, multi-step collaboration workflow | A pre-written standard operating procedure — call out and it runs |
| Plugins | Extend "what can be connected" — let Cowork read/write more external services/data sources | Add a dedicated tool to the toolbox |

- The two work together: a Skill can fully call on the connection capability provided by a Plugin internally (for example, the Skill "organize this week's files and sync to Feishu" would internally use the Feishu-connection Plugin, echoing 4.7).

> Instructor tip: the specific product names and settings entry points for Skills/Plugins will change as Claude Desktop versions iterate. Verify the actual feature names and operation paths against the current version before class. The focus of this lesson is to clearly explain the methodology of "packaging a workflow + one-click triggering"; demonstrate the specific interface according to the latest version.

### III. Hands-On: Package a Repetitive Cowork Task into a Skill

Using the "file organization" task repeatedly practiced in this chapter as an example:

**Step 1: Map Out the Fixed Workflow**

Revisit the file-organization steps learned in 4.4: set categorization rules → generate a categorization plan → confirm → execute → self-check — this is already a validated, fixed workflow.

**Step 2: Package It as a Skill**

```
> I'd like to package the task "organize my downloads folder every week" into a Skill:
> Trigger occasion: whenever I organize my downloads folder each week
> Fixed steps: categorize by file type → generate a categorization plan for me to confirm → execute → self-check the categorization results
> Please help me organize this workflow according to Skill conventions
```

**Step 3: Bind It to a Quick-Trigger Method**

Following whatever method the current version of Claude Desktop supports (shortcut key, fixed phrase, menu entry, etc.), set this Skill up so it can be invoked quickly, and demonstrate the binding process live.

**Step 4: Verify the "One-Click Trigger" Effect**

Trigger it once in practice, and observe whether — without needing to redescribe the task details — the Skill automatically executes according to the packaged workflow up to the point where "your confirmation is needed."

### IV. What Kinds of Collaboration Workflows Are Worth Packaging as a Skill

- Echoing the judgment criteria from Chapter 7's 7.3: involves multiple steps, has clear sequential logic, will be used repeatedly, and requires consistent execution standards;
- Types especially well-suited to packaging in the Cowork scenario: fixed-cycle organization tasks (weekly reports, monthly archiving), fixed-format analysis tasks (competitive analysis framework), and fixed cross-tool sync tasks.

## Frequently Asked Questions

**Q: What's the difference between a Skill and the prompt templates from 4.8?**
A: A prompt template requires you to manually open it, copy it, and adjust parameters as needed; a Skill packages the entire "trigger + execute" workflow, and the trigger method is much lighter (one click/one phrase). The two can be used together — the template is the raw material, and the Skill is the finished product that packages the material together with its trigger method.

**Q: After packaging a Skill, is human confirmation still needed?**
A: Yes. Echoing the safety thread from Chapter 1, for steps involving modification/deletion operations, the Skill will still retain the necessary confirmation checkpoints internally. What's one-click-triggered is "the launch and execution of the workflow," not "completely skipping human gatekeeping."
