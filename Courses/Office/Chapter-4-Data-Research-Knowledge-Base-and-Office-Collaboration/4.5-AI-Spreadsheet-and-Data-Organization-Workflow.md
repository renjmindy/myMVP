# 4.5 | AI Spreadsheet and Data Organization Workflow

## Learning Objectives

- Master the core workflow for using AI to process spreadsheet data: cleaning, merging, categorizing, and aggregating;
- Be able to write clear descriptions of spreadsheet processing requirements, avoiding the risk of "data being silently altered incorrectly";
- Complete a real spreadsheet data-processing task, and learn to use visualization to help verify results (echoing the `dataviz` skill).

## Suggested Duration

30 minutes (in-depth hands-on)

## Prerequisites

- Have completed 4.4 and understand the "design the rules first, then execute" organizational methodology, which this lesson carries over into the spreadsheet scenario.

## Course Outline

### I. Common Types of Spreadsheet-Processing Tasks

| Type | Typical Requirement |
|---|---|
| Data cleaning | Remove duplicate rows, standardize formats (date/currency/units), fix obvious errors |
| Data merging | Merge spreadsheets from multiple sources into one, based on shared columns |
| Data categorization/tagging | Tag each row with a category label based on its content |
| Data aggregation/pivoting | Group and summarize by dimension, generate a summary table |

### II. Safety Reminders for Spreadsheet Processing (Front-Loaded and Important)

- Spreadsheet data tasks tend to be "results-oriented," making it easy to overlook process review — be sure to build the habit of "clarify the rules before processing, spot-check after processing";
- When dealing with sensitive data such as financial or customer records, prioritize processing it locally/in a controlled environment, and comply with data privacy regulations;
- **Always back up the original data.** Any AI-assisted data processing should be performed on a copy, keeping the original file as a fallback baseline — this is a more fundamental safety net than "permission confirmation."

### III. Hands-On: Data Cleaning

1. Prepare a sample spreadsheet with obvious issues (duplicate rows, inconsistent formats, missing values);
2. Task description:

```
> Please clean this spreadsheet data:
> 1. Remove fully duplicate rows
> 2. Standardize the date format to YYYY-MM-DD
> 3. Flag rows missing key fields (such as name, amount) — don't auto-fill them, just flag them
> Please show me a before/after comparison summary first, then ask me to confirm before applying the changes
```

3. Review the comparison summary, and apply the changes once confirmed correct.

### IV. Hands-On: Data Merging and Categorization

1. Prepare two sample spreadsheets that share a common column (such as "Customer ID") but have different content;
2. Task description:

```
> Please merge these two spreadsheets into one, based on the "Customer ID" column, keeping all columns from both sides;
> After merging, please tag each customer as "high/medium/low" spending based on the "spending amount" column (please confirm the specific threshold criteria with me first)
```

3. Emphasize that categorization criteria need to be specified down to "concrete numeric ranges," to avoid subjective, vague standards like "high spending" being arbitrarily defined by the AI.

### V. Hands-On: Data Aggregation and Visual Verification

```
> Please aggregate the sales data by two dimensions — "month" and "product category" — and generate a pivot table
```

- Once the aggregation is complete, it's recommended to use a chart to quickly verify whether the aggregation logic is reasonable (echoing the `dataviz` skill — if chart generation is involved, the instructor can invoke this skill at this point to standardize color choices and presentation);
- Using a chart to "spot at a glance" whether the data matches common sense (e.g., a sudden spike or drop in a particular month) is more efficient than checking row by row — this is also a reapplication of the outlier-thinking mindset (learned in 3.4) to the data-processing scenario.

### VI. Result Verification Checklist

Once processing is complete, help learners build the habit of verification:

- [ ] Does the change in row count before and after match expectations (row count should decrease after deduplication cleaning; row count after merging should match the expected logic)?
- [ ] Spot-check 5–10 rows to confirm the original data matches the processed data;
- [ ] Do key statistics (sum, average) roughly match the order of magnitude of a rough estimate from the original data?

## Frequently Asked Questions

**Q: Could the AI miss rows or make calculation errors when processing large spreadsheets?**
A: When processing very large spreadsheets, there is a real risk from context limitations and precision issues. Be sure to perform result verification (see the checklist above); for important business data, it's recommended to cross-check with traditional tools (Excel formulas, scripts) rather than relying solely on a single processing result.

**Q: Can the AI directly modify the original Excel file?**
A: Yes, but it is strongly recommended to work on a copy first, and only replace the original file once the result is confirmed correct, to avoid irreversible data damage.
