# 4.2 | Cowork Core Feature Modules Explained

## Learning Objectives

- Master each of the core feature modules in the Cowork interface and their purposes, one by one;
- Be able to proactively choose the appropriate feature module based on the task at hand, rather than only using the most basic chat input;
- Understand how the various modules work together.

## Suggested Duration

25 minutes

## Prerequisites

- Have completed 4.1 and are familiar with the basic Cowork task lifecycle.

## Course Outline

### I. Overview of Feature Modules

Walk learners through the following modules one by one (the instructor should verify the actual entry point names and locations against the current product version, and update screenshots before class):

| Module | Function |
|---|---|
| Task/Progress Panel | Shows the breakdown steps and completion status of the current Cowork task |
| Data Association Area | Manages the scope of files/data associated with the current task |
| Conversation Interaction Area | Similar to the regular conversation mentioned in 4.1, but with context anchored to the current task |
| Output Preview Area | Similar to Artifacts, displaying generated documents/spreadsheets/web pages and other results |
| Version History/Revision Log | Traces back key nodes and modification history during task execution |

### II. Task/Progress Panel: Visualizing the Collaboration Process

- Complex tasks are broken down into multiple sub-steps, and the progress panel lets you know "which step we're on now" at any time;
- Hands-on demonstration: Give a slightly more complex task (e.g., "organize 20 files and generate a summary report"), and observe how the progress panel updates as execution proceeds;
- Emphasize the value: compared with pure conversation, the progress panel turns the collaboration process from a "black box" into a "trackable workspace" — this is also one of the core differences between Cowork and regular chat.

### III. Data Association Area: Managing the Task's "Material Boundary"

- This echoes the concept of "workspace boundaries" from Chapter 2 — Cowork's data association area is its boundary-management tool;
- Hands-on: demonstrate how to add new files or remove unneeded files mid-task, and observe how the AI adjusts its analysis scope accordingly;
- Reminder: the scope of associated material directly affects task quality. It's recommended to follow the principle of "just enough, and focused" — too much irrelevant data will dilute analysis precision.

### IV. Output Preview Area: What You See Is What You Get

- Similar to Artifacts (learned in 1.2), but more closely tied to the current task's context;
- Hands-on demonstration: after a task produces a spreadsheet or document, show how to view it directly in the preview area and request local edits (e.g., "unify the date format in column 3") without having to redescribe the entire task.

### V. Version History/Revision Log: A Traceable Collaboration Process

- For tasks with multiple rounds of revision (e.g., repeatedly adjusting a report), the version history lets you roll back to an intermediate version, or compare the differences between versions;
- Hands-on demonstration: deliberately have the AI make an unsatisfactory edit, then demonstrate how to roll back to the version before the edit and redirect the adjustment.

### VI. Hands-On: Module Coordination Exercise

Give learners a comprehensive task, requiring them to proactively use at least 3 modules to complete it:

```
Task: Organize a batch of customer feedback documents, generate a categorized summary table, and flag the 3 pieces of feedback that need priority handling
```

Require learners to, during the task:
1. Use the data association area to manage the scope of material;
2. Use the progress panel to keep track of the execution stage;
3. Make local adjustments to the result in the output preview area.

## Frequently Asked Questions

**Q: Are all of these modules used in every task?**
A: No. A simple task may only need the conversation interaction area and the output preview area; the modules form a toolbox that is used as needed — the more complex the task, the more you'll appreciate the value of the progress panel and version history.

**Q: Can the output be exported directly for use?**
A: Generally, export to common formats (such as documents and spreadsheets) is supported. The specific formats supported depend on the current product version — it's recommended to verify this before class and demonstrate a complete export process once.
