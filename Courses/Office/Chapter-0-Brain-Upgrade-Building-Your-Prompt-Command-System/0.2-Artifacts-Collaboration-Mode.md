# 0.2 | Artifacts Collaboration Mode: Making Your Output Your Working Interface

## Learning Objectives

- Understand that Artifacts is not just "a place where results get generated," but a collaboration interface that can be continuously iterated on;
- Master the method of using Artifacts for multi-round iterative collaboration, as distinct from the "generate once, use it if satisfied, ask again from scratch if not" approach;
- Complete one hands-on exercise of multi-round iterative Artifacts collaboration.

## Suggested Duration

25 minutes

## Prerequisites

- 0.1 (Structured Prompt Framework) must be completed. This lesson builds on that foundation and focuses on one specific collaboration mode.

## Course Outline

### I. How Most People Misuse Artifacts

- Common usage: have Claude generate a document/webpage/chart, glance at it, and if unsatisfied, ask the whole thing again from scratch — effectively treating Artifacts as "disposable scratch paper";
- This usage wastes the real value of Artifacts — it is a **working interface, independent of the chat history, that can be continuously referenced and modified**. You can make precise, local adjustments to content that has already been generated, without having to describe the entire task from scratch every time.

### II. The Core Idea of the Artifacts Collaboration Mode

```
Round 1: Give a structured task, generate the first version of the Artifact
  ↓
Round 2: Raise specific, local revision requests targeting the first version's issues
          (rather than re-describing the entire task)
  ↓
Round 3: Continue iterating on details until satisfied
  ↓
Final version: The deliverable/usable result
```

- Analogy: this is more like "revising drafts with a designer" than "hiring a different designer to redo the whole thing every time" — you preserve the results of the previous version and raise precise revision requests only for the specific issues.

### III. Hands-on: A Complete Round of Multi-Round Iterative Collaboration

**Round 1: Structured task, generate the first version**

```
Goal: Create a webpage for a personal year-end review
Context: For sharing with friends and colleagues; tone should be relaxed but still professional
Format: A single-page webpage with three sections: "What I did this year, What I learned, Plans for next year"
Constraints: No longer than one and a half screens
```

**Round 2: Precise, local revisions (the key demonstration)**

If unsatisfied, avoid saying something like: "Redo it" (vague, and it discards what's already been achieved);

Instead, say something like:

```
The content in the "What I did this year" section is good — keep it unchanged;
But the tone in the "What I learned" section is too formal — please make it more conversational;
Also, could you change the overall color scheme to warmer tones?
```

Have learners observe whether Claude accurately understands "which part to keep, which part to change," adjusting only the specified parts rather than tearing down and rebuilding the entire page.

**Round 3: Continue refining details**

```
The color scheme works now, but the text in the "Plans for next year" section is a bit small and hard to read — please bump it up a size.
```

### IV. When to Use the Artifacts Collaboration Mode

- The output has a certain level of complexity and requires repeated polishing (documents, webpages, charts, structured tables);
- You have a specific, describable judgment about "what's unsatisfying," rather than a vague "something feels off but I can't quite say what" (in the latter case, it's recommended to go back to the structured framework from 0.1 and rethink the goal and format requirements first).

### V. Class Discussion: Why "Local Revisions" Are More Efficient Than "Regenerating from Scratch"

Guide learners to compare the experience: if you re-describe the entire task from scratch every time you're unsatisfied, it's not only time-consuming, but an incomplete re-description can also cause you to lose parts that were already right in the first round; precise, local feedback lets Claude concentrate its "firepower" on the actual problem points, making overall collaboration more efficient and the result more coherent.

## Frequently Asked Questions

**Q: Won't the content in an Artifact get messier and messier after many rounds of revision?**
A: If each round's feedback is specific and clear enough, usually not. If you find after a few rounds that things have drifted off course or become logically confused, you can choose to go back to a version you were satisfied with and restart local iteration from there, rather than continuing to compound the mistake.

**Q: When should you give up on iterating and just regenerate from scratch?**
A: If the overall direction of the first round has a fundamental problem (for example, the structure is completely wrong), local revisions are unlikely to save it. In this case, giving a clearer structured task from scratch is more efficient than repeated local revisions.
